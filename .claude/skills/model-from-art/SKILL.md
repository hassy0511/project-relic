# 絵から 3D モデルを作る（再構築の手順）

ハル（`haru_r`）で確立した手順。**絵をそのまま形と色の材料にする**ので、絵に忠実で、外部のサービスが要らない。
ハルでは約 15 時間かかったが、下の「無駄だったこと」を避ければ **1 体 4〜6 時間** を目標にできる。
結果と画像：`docs/art_orders/W1_ハル再構築の結果.md`、`docs/art_orders/haru_r_trial/`。
絵の条件：`docs/art_orders/01_3D変換用の絵の条件.md`（発注するときにそのまま渡す）。

## 1. 最初に確かめること（10 分）

1. 環境：`bash tools/setup_blender.sh`（bpy・scipy・scikit-image）、`bash tools/setup_godot.sh`（Godot と撮影用の Vulkan）。
   作業環境は作り直されるので、セッションごとに必要。
2. 絵：`01_3D変換用の絵の条件.md` の必須の絵がそろっているか。**足りない絵は作業を始める前に追加で発注する**
   （ハルでは首・襟、手、靴底、胴の横が絵に無く、最後まで粗が残った）。
3. 絵の間の整合：全身の絵を並べ、足の裏の行・頭頂の行・中心の列がそろっているかを数字で測る（`views.py` が出す）。
   斜めの絵の実際の角度は **発注どおりとは限らない**（ハルは 45 度の発注で約 31 度だった）。左右の脚・腕の間隔の比から求める
   （`carve.py --stage calib`）。

## 2. 流れとコマンド（すべて `.venv-blender/bin/python`、スクリプトは `tools/blender/recon/`）

一度に作る：`npm run haru:recon`・`npm run yana:recon`（`build_char.py --char <id>`。中身の指紋で変わった段だけ作り直す。`--list`、`--from 段`、`--only 段`、`--review`）。下の表の `build/recon/` はハルの作業のフォルダ（キャラクターごとに 5 章の `work`）。

| 段 | スクリプト | やること | 時間 |
|----|-----------|---------|------|
| views | `views.py` | 絵の取り出し（`build/recon/src/`）、外形のマスク、最初の較正 | 1 分 |
| calib | `carve.py --stage calib` | 斜めの角度・横位置・縮尺の追い込み → `calib.json` | 3 分 |
| hull | `carve.py --stage hull` | 形の場：**体は「レンズ」**（正面の外形をふくらませた丸い断面、`fair.py`）＋**頭・髪・ゴーグル・耳は部品**（`hair.py`） | 3 分 |
| mesh | `carve.py --stage mesh` | 面にする → 外形の縁だけを絵の外形へ寄せる（`snap.py`）→ 掃除・間引き（約 4.5 万三角形）→ UV（`uvparts.py`：平面で約 30 の部位に切る） | 5 分 |
| face | `face.py` | 高解像度の顔の絵を全身の頭に重ね、4 表情を 2×2 の画像にする（`face_atlas.png`） | 3 分 |
| gun | `gun.py` | 持ち物：真横の外形を押し出し、厚みを付け、真横の絵を両面に貼る | 2 分 |
| texture | `texture.py` | 各方向の絵を「その方向から見えている面」にだけ貼る。腕の陰になる胴には腕の色を移さない。顔は材質 `haru_face` | 10 分 |
| joints / rig | `joints.py`、`tools/blender/models/ai_character.py` | 関節の推定、重み、腕を下ろした基準の姿勢、標準の 20 本の骨と 14 動作、銃・光刃・目印、右手の拳（シェイプキー `fist`） | 5 分 |
| review | `review.py`、`ingame_shots.py` | 確認の画像（絵との比較、表情、動作、関節、Godot の画面） | 15 分 |

Godot：`godot/assets/models/<名前>.glb` に置き、`tools/godot.sh import` → `tools/godot.sh test` → `tools/godot.sh run --fixed-fps 60 -- --demo=/tmp/d`。

## 3. 進め方（順番が大事）

1. **まず全段を一度通す（縦に 1 本）**：較正 → 形 → 色 → 骨 → Godot まで、粗くてもよいので最初の 2 時間以内に通す。
   色を付けると形の粗の多くは目立たなくなる。**色なしの形だけで完成度を追わない**（ハルでは色なしの形の判定と直しに 6 時間以上使ったが、色を付けたら半分以上は見えなくなった）。
2. 通したら、**Godot の画面と絵との比較の画像**で、目立つ順に直す。直す対象の優先度：
   顔 ＞ 髪の外形 ＞ 正面・背面の色 ＞ 横・斜めの色 ＞ 手 ＞ 首・襟 ＞ 靴 ＞ 細部。
3. 1 回の直しは 1 つの問題に絞り、直したら同じ角度の画像で前と比べる。

### 担当を分けるとき（Workflow や Agent）
- 並行できる：形（hull・mesh）／顔（face）／持ち物（gun）／骨付けと Godot の準備（仮の色のモデルで先に通す：`build_haru_r.py --standin`）。
- 色（texture）は形の後。確認と直しは色の後。
- **各担当に時間の区切りを必ず付ける**（「開始時に `date` を見て、2 時間で最良の版を仕上げて報告」）。区切りが無いと 1 担当が 5 時間以上試し続けた。
- 判定役は「色を付けた状態の画像」と「Godot の画面」で判定させる。色なしの形だけの判定は、面の筋・穴などの技術的な欠陥に限る。
- **こまめにコミットする**。作業環境が途中で作り直されると、担当の報告は失われる（`build/` の中の途中の成果は残る）。
  長い作業の再開では「前の担当の成果が `build/recon/` にある。やり直さずに確かめて続けよ」と伝える。

## 4. 無駄だったこと・効いたこと（ハルの記録）

| 無駄だった | 代わりに |
|-----------|---------|
| 輪切りごとに断面を決める視体積 → 横筋・段・ひれが消えず 5 時間 | 最初から体は「レンズ」（`fair.py`）、外形は `snap.py` で縁だけ寄せる |
| 髪を外形から削り出す → とげの生えた卵 | 最初から「頭の土台＋先の細い房」の部品（`hair.py`）。房は外形に合うよう向き・長さだけ当てはめる |
| ゴーグルを外形から押し出す → 一枚板 | 絵から枠の形をなぞって部品にする |
| Smart UV Project → 1,780 の島 | 平面で部位に切る（`uvparts.py`） |
| 色なしの形の判定を何度も繰り返す | 早く色を付けて全体で判定する |
| 担当に時間の区切りが無い | 区切りを付け、区切りで最良の版を仕上げる |

効いたこと：
- 斜めの絵の角度を、左右の手足の間隔の比から測る（見た目の外形の一致では角度が決まらない）。
- 絵に無い向き（左前など）は、右前の絵の左右反転を「仮想の視点」にする。ただし**左右非対称の部品**（片側だけの板・籠手）は、正面の絵の左右の色の差から自動で見つけて除く。
- 色は「見えている面にだけ」貼る（視点ごとの深さの画像で判定）。見えない面は、同じ部位の近くの色で埋める。
- 顔は材質を分け、表情の 2×2 の画像を `uv1_offset` で切り替える（`player_view.gd`）。
- 右手の拳はシェイプキーにし、基準の姿勢は絵どおりの開いた手のまま残す。
- 確認は、なめる光（斜め上からの強い光）の灰色の画像と、絵と同じカメラの比較の画像の 2 種類。
- **腕を外した真横の絵**（`*_side_right_noarms.png`）が効く：胴の横の色をそこから取れる（腕の色が胴に付かない）うえ、
  腕のある真横の絵との色の差で「絵の腕」の範囲が切り出せ、胴に重なって外形にならない前腕の前後の位置を合わせられる（`snap.py`）。
- 真横の外形はあごの下まで前へ出ているので、体のレンズがあごの下に棚を作る。首の前の面より前の体を切る（`fair.py` の `THROAT_CUT`）。
- 隠れている側の手（左手は右真横で体の向こう）の縁を外形へ寄せると、指が削られて爪のようになる。寄せない。
- 追加の斜めの絵も角度は測る（W1-00b の「45 度」は約 46.5 度）。絵どうしで腕の位置が数 cm 食い違うので、形はどれか 1 枚に
  全部は合わせず、色は視点ごとの合わせ込み（texture.py の光学的流れ）で吸収する。

## 5. キャラクターごとの設定（2 体目から）

流れは `build_char.py --char <id>`（`npm run haru:recon`・`npm run yana:recon`）。キャラクターの違いは
`tools/blender/recon/chars/<id>.json` だけに書く（読み込み口は `char.py`。各段は環境変数 `RECON_CHAR` で同じ設定を読む）：
- `art`（絵のブランチ・フォルダ）、`work`（作業のフォルダ。ハル `build/recon`、ヤーナ `build/yana`）、`out_glb`、`source_files`
- `views`：視点ごとの絵と最初の方位角。`three_quarter` は「形に使う斜めの絵」の役（ハルは約 31 度の古い絵、ヤーナは右前 45 度の絵を当てる）
- `face`：顔の絵・表情の絵・表情の順（アトラスの左上・右上・左下・右下。ゲームの区画の番号）
- `height_m`：本来の身長。**再構築は基準の身長 1.55m の座標で行い**（ハルで決めた長さの定数がそのまま使える）、骨付けの段で
  `ai_character.py --final-height` が骨の物体を一様に拡大する（ヤーナ 1.72m）
- `rig_args`（持ち物：ハルは銃・光刃・拳、NPC は `--no-weapon`）、`stages_skip`（ヤーナは `gun` なし）
- `params`：各スクリプトの定数の上書き `{"モジュール.定数名": 値}`。書かなければハルの値。2 体目で上書きしたもの：
  頭と首の高さ（`carve.HEAD_Z`、`fair.BODY_TOP`・`THROAT_CUT`、`snap.FREEZE_Z`）、頭の断面の節・耳・首・前髪・房の表・頭の部品の有無
  （`hair.SKIN`・`EAR`・`NECK`・`BANGS`・`LOCK_TABLE`・`PARTS`：ヤーナはゴーグルとベルトなし）、UV の切る高さ（`uvparts.CUT_Z`・`ARM_GAP`）、
  顔の絵の範囲と目印・表情で差し替える範囲（`face.*`）、色の後処理の高さ・左右非対称の部品・視点の重み・耳の肌色（`texture.*`）、
  左の前腕の前後の合わせ（`snap.LEFT_ARM_GAIN`）、関節の表（`joints.ART_XZ`）。刈り上げは `hair.CAP.undercut`
- 値の読み方：`calib.json` のカメラで絵に 1cm の格子を重ねた画像を作り、あご・首・耳・関節を読む（1 体 20 分ほど）。
  絵の縮尺が同じなら（頭頂・足の裏の行がそろう）、多くの値はハルの値の近くになる。

確認：`build/<id>/review/`（`--review`）、Godot の住人は `godot_npc_showcase.gd`。結果：`docs/art_orders/W1_ヤーナ3D化の結果.md`。
新しいキャラクター：`chars/haru.json` を写して名前・絵・視点・顔を書き、`--only views`・`--only calib --force` で較正し、格子の画像から
`params` を埋めてから `--from hull` で通す。

人型でないもの（ナゴミ、番機）：
- 丸い・角ばった機械は、視体積（正面・真横・上面の外形を掛け合わせる）がそのまま使える。**上面の絵が必須**。
- 部品が分かれて動くもの（ナゴミの殻、番機の脚）は、部品ごとの絵（分解図）から部品ごとに作り、骨の代わりに部品の階層で動かす。
- 表情は顔の画像の切り替えの代わりに、発光の色・明るさ・殻の開き具合で出す。

## 6. 完成の目安（判定の基準）

- 絵と同じカメラで重ねたとき、正面・背面・真横の外形の重なり 0.96 以上。
- Godot のふだんのカメラの距離で、絵のキャラクターだと分かる（色・部品・左右の違い）。
- 顔の 4 表情が継ぎ目なく切り替わる。
- 動作（走り・跳躍・斬撃・被弾）で、関節がつぶれない・腕が頭に刺さらない・持ち物が手から離れない。
- テスト（`tools/godot.sh test`）と自動の見本が通る。
