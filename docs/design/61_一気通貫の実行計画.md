> `60_開発計画.md` の ①MVP と ②本気ステージのうち、**Codex の絵を待たずに進められる作業**を、止まらずに一気に進めるための計画。
> ユーザーの「ゴー」が出てから着手する。
>
> **更新（2026-09-27）**：ユーザーのゴーは「MVP まで」の意味だった。そのため **CP1（MVP 完成）で報告して止まる**。CP1 以降は、改めてゴーをもらってから進める。進み具合は `docs/progress.md`。

## 1. 絵を待たずに進められるもの／待つもの

| 絵を待たずに進める | 絵が届いてから行う |
|------------------|------------------|
| プログラムの土台、操作、カメラ、移動、ロックオン、主武器、光刃、特殊武器（ドリル） | 本番のキャラクター・敵・ボスのモデル |
| 敵 5 種の AI、ボス「閂」の行動 | 本番のテクスチャと色 |

| 会話・イベントの仕組みと、**第1章の全台本** | UI の本番の見た目 |
| 工房、店、依頼、経済、回収屋の印 | エフェクトの本番の見た目 |
| **第1章の全 20 部屋と町を、仮の見た目（グレーボックス）で作る** | 地形の飾り付けと照明の焼き込み |
| 標準の人型の骨と、アニメーション一式（仮の体型で作り、絵の確定後に合わせ直す） | 本番の体型に合わせたアニメーションの仕上げ |
| BGM・効果音（自作のシンセ） | — |
| UI の機能（仮の見た目） | — |
| 自動テスト、リプレイ、ボットによる第1章の自動通しプレイ、CI | — |

## 2. 作業の流れ

| 順 | 作業 | 内容 |
|----|------|------|
| 1 | 土台 | 開発環境の構築（npm、Blender 用の Python 環境、テスト、CI）、ループ、入力、物理、カメラ |
| 2 | 手触りの核 | 移動、ロックオン、主武器、光刃、ダッシュ、ヒットストップ。手触りの数値テスト。調整パネル |
| 3 | 制作の流れ | Blender スクリプトによる仮のハルと仮の番機、アニメーション、GLB の読み込み |
| 4 | **CP1：MVP** | `60_開発計画.md` 3 章の内容。**ここで報告し、試遊版を渡す（待たずに次へ進む）** |
| 5 | 戦闘の中身 | 敵 5 種、ボス「閂」、ブレイクドリル、怯み、ダメージ、撃破 |
| 6 | 世界と進行 | エリア、扉、宝箱、仕掛け、セーブビーコン、近道、フラグ、イベント、会話、セーブ |
| 7 | 第1章の組み立て | 町と遺構 B1〜B4 の全 20 部屋（仮の見た目）、全イベントと全会話、工房・店・依頼 |
| 8 | 音と UI | BGM 5 曲前後、効果音一式、HUD・会話・メニュー（仮の見た目） |
| 9 | 自動確認 | ボットによる第1章の通しプレイ、リプレイ、ブラウザでの撮影 |
| 10 | **CP2：第1章の仮組み完成** | 仮の見た目で、第1章を最初から最後まで約 90 分遊べる。**ここで報告して止まる** |

- 手順 5 以降の作業を進めながら、CP1 の試遊の感想は、届いた時点で数値の調整として反映する。
- Codex の絵が途中で届いた場合（W0 の画風決定、W1・W2）は、その時点で見た目の反映を差し込む。

## 3. 報告と停止のルール

| 場面 | 動き |
|------|------|
| CP1（MVP 完成） | 報告して試遊版を渡し、**止まる**（ユーザーの指示により変更） |
| CP2（第1章の仮組み完成） | 報告して**止まる**。第2章以降の量産は、本気ステージの了承を得てから（`60_開発計画.md` どおり） |
| 範囲や方向性を変える判断が必要になったとき | 進められる別の作業を続けつつ、確認を求める |
| 設計書に書いていない細部 | 設計の意図に沿って決め、報告にまとめて書く |

- こまめにコミットしてプッシュする（コンテナが消えても作業が失われないように）。
- 進み具合は `docs/progress.md` に記録する。

## 4. 着手前に決めてほしいこと

1. **リポジトリの公開設定**：現在このリポジトリは**公開（public）**になっている。企画書・シナリオの結末・今後のソースコードと絵がすべて誰でも見られる状態。販売を考えるなら、**非公開（private）にすることを強く勧める**。
2. **試遊版の届け方**
   - 非公開にする場合：Cloudflare Pages（無料、ユーザーのアカウント設定が必要）か、手元で `npm run dev`。
   - 公開のままにする場合：GitHub Pages で自動公開できる。
3. **MVP の感想を待たずに先へ進めてよいか**（推奨：進める。感想は数値の調整として後から反映できる）。
