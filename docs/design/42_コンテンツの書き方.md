# コンテンツの書き方（部屋・扉・宝箱・仕掛け・イベント・会話）

> 段階 C（第1章の 20 部屋と町）を作る人が、**コードを触らずデータだけで部屋を作る**ための手引き。
> 動く見本は `godot/content/areas/sample.json`（広間・動力の試験室・倉庫の 3 部屋）。確認：`tools/godot.sh shot -- --room=sample.gym`（ブラウザ版は `…/?room=sample.gym`）。
> 実装は `godot/scripts/sim/`（`world.gd`・`room_geo.gd`・`cond.gd`・`story.gd`・`economy.gd`・`game_sim.gd`）。

---

## 1. ファイルの置き場所

| 置く場所 | 内容 |
|----------|------|
| `godot/content/world.json` | **目次**。どのファイルを読むか、始まる部屋。新しいファイルを足したらここに書く（ブラウザ版でも読めるよう、フォルダの自動探索はしない） |
| `content/areas/<エリア>.json` | エリア 1 つ＝部屋の集まり。部屋の id は「エリア id.部屋名」（例：`ch1.r02`） |
| `content/dialogue/*.json` | 会話（id → 行の並び） |
| `content/events/*.json` | イベント（id → 手順の並び） |
| `content/items.json` | アイテム・素材・遺物の名前と売値 |
| `content/economy.json` | 店・工房・ギルドの依頼 |

`world.json` の例：

```json
{ "start": { "room": "mvp.main", "spawn": "start" },
  "areas": ["areas/mvp.json", "areas/ch1_b1.json"],
  "dialogue": ["dialogue/mvp.json"], "events": ["events/mvp.json"],
  "items": "items.json", "economy": "economy.json" }
```

- 単位はメートル、角度は**度**（目印の yaw も度。GLB の目印は従来どおりラジアンに変換済み）。向き 0 は +Z、90 は +X。
- 座標は `[x, y, z]`。**y は上**。
- ほかの部屋を指すとき、ドットのない名前は同じエリアの部屋（`"to": "r03"`）。

## 2. 部屋

```json
"r02": {
  "name": "ジャンク溜まり",
  "map": { "floor": "B1", "x": 1, "y": 0, "w": 1, "h": 1 },
  "geometry": [ …形… ],
  "markers": { "start": { "pos": [0,0,-8], "yaw": 0 }, "from_r03": { "pos": [9.5,0,0], "yaw": -90 } },
  "playerStart": "start",
  "objective": "…",
  "props": [ … ], "triggers": [ … ], "enemies": [ … ], "checkpoints": []
}
```

- `markers`：名前つきの位置。移ってくる先（`spawn`）はここで決める。**出口の範囲の中に置かない**（着いた瞬間にまた移ってしまう。入口の 2m 以上手前に置く）。
- `map`：地図用（階層名・格子の位置・大きさ）。入った部屋は自動で記録される（フラグ `visited.<部屋 id>`）。
- GLB の地形を使う部屋は `"model": "levels/xxx.glb"` を足す（`m_` で始まるノードが目印になる。`geometry` や `markers` を足してもよい）。MVP の部屋がその例。
- `"mood"`：空と光の雰囲気。`outdoor`（屋外。フラグ `ch1.night` が立つと停電の夜）・`dawn`（夜明け）・`interior`（屋内）・遺構の階層ごとの色 `ruin_b1`（外殻層：割れ目の暖かい光）`ruin_b2`（配管層：暗い青灰）`ruin_b3`（駆動層：青銅とオレンジ）`ruin_b4`（心臓部：紫と青緑）。省略は昼。`"lights": [ { "pos": [x,y,z], "color": "#ffc27a", "range": 12, "energy": 1.5 } ]`：部屋の明かり（街灯・窓・室内灯）。
- どの部品にも `"when": 条件` / `"unless": 条件`（4 章）を付けると、その部屋に入った時点で条件に合うときだけ置かれる（イベントのあとで住人の位置が変わる、など）。
- 位置は `"at": "目印の名前"` か `"pos": [x,y,z]`（＋ `"yaw": 度`）のどちらでも書ける。

### 2.1 形（geometry）：灰色の箱から部屋を組む

| `t` | 書き方 | 内容 |
|-----|--------|------|
| `box` | `pos`（底の中心）, `size` [幅,高さ,奥行き], `yaw` | 箱。柱・壁・段・足場 |
| `ramp` | `pos`, `size`, `yaw` | 斜面（ローカルの +Z 側が高い）。45 度までは歩いて登れる |
| `stairs` | `pos`, `size`, `steps`, `yaw` | 階段（1 段 0.35m 以下で自動で登れる） |
| `shell` | `pos`（床の中心）, `size`（**内側**の寸法）, `thick`, `ceiling`, `openings` | 床＋四方の壁（天井は `"ceiling": true` のとき）。`openings` で壁に穴をあける |

`openings` の 1 つ：`{ "side": "e", "at": 0, "w": 2.5, "h": 3.5, "y": 0 }`。`side` は n（+Z）・s（−Z）・e（+X）・w（−X）の壁、`at` は壁の中心からのずれ、`y` は穴の下端の高さ。
色を変えるには各形に `"tint": "#8a8f99"`。見た目は灰色の格子（本番の地形に差し替える前提）。
本番の見た目は、部屋に `"kit"`（面の材質）と `"dress"`（飾りの部品）を足して付ける（14 章）。当たり判定は geometry のまま。

寸法の目安は `30_レベルデザイン設計.md` 1 章（通路 4m 以上、扉 2.5×3.5m、戦闘の部屋 18m 四方以上、など）。

### 2.2 詰みを作らない（入れるのに出られない所・宙づり）

ハルが行ける所からは、どこからでも出口か部屋の本筋へ戻れるようにする（2026-10-15 の詰み探しで決めた）。

- **穴・溝の底**：跳んで出られる深さ（段 1.8 m まで）か、底を奈落の高さ（`Player.KILL_Y` の y −30）より下にする（落ちると 10 ダメージで直前の動かない足場へ戻る）。
  底から出る道（坂・段）を作るなら、底のどこからでも見える所に置く（駆動回廊 r12 は、穴の奥の端の坂が見つからずに詰んだ）。
- **すき間**：立てる面（箱・台・宝箱・住人の頭・端末の上）と壁・ほかの箱の間を **0.35〜0.75 m** にしない。体（直径 0.7 m）が縁の角に載って、
  立てない（跳べない）まま宙に止まる。0.35 m より狭く寄せる（体の真ん中が縁から出ない）か、0.75 m 以上空ける（下の床まで落ちて、すき間の端から出られる）か、
  低いほうの高さまで箱でふさぐ。家のベッドと壁、ギルドのバートンと受付台、宝箱と壁、縦坑の足場と壁がこれで詰んでいた。
- **段差**：歩いて上る段は 0.17 m 以下か 0.25〜0.35 m にする。約 0.18〜0.24 m の段は、体の丸い底が段の角に当たったまま止まり、歩いては上れない
  （下りる・跳んで上がるのはできる。`Phys.move_character` の今の制限。`ReachScan.BAD_STEP_LO`〜`BAD_STEP_HI`）。
- **跳ぶボタンが「話す・調べる」になる所**：住人・端末・ビーコンのそば（届く距離の中）では跳べない。そこから跳ばないと出られない作りにしない。
- **動く足場**：乗っていないハルの体の手前（5 cm）で止まり、どくと動き出す（`GameSim._mover_overlaps_player`）。床すれすれまで下りるリフトの下に立っても、押しつぶされない。
- **確かめ方**：`tools/godot.sh run --script res://tests/scan_traps.gd -- [部屋 id の一部]` が、部屋を形だけで調べて詰み・限界の跳びでしか出られない所・
  宙づりの候補を出す（`godot/tests/reach_scan.gd`。部屋に居るときの本筋の段階は `ReachScan.CH1_STATES`）。`tools/godot.sh test` の
  `test_traps:test_ch1_rooms_no_traps` が第 1 章の全部屋を調べ、宙づりの候補には実際のゲームで体を置いて確かめる。新しい部屋・段階を足したら `CH1_STATES` に足す。

## 3. 置く物（props）

どれも `"id"`（**世界で重ならない名前**。例：`"ch1.r02.chest1"`）と位置が要る。

| `type` | 主なキー | 内容 |
|--------|----------|------|
| `exit` | `to`, `spawn`, `size`, `lock?`, `text?` | **別の部屋への出口**。範囲に入ると移る（暗転し、オートセーブ）。開口の位置に置く。`lock` が偽なら通れず `text` を出す |
| `door` | `size`, `lock?`, `opens`, `side`, `consume?`, `text?`, `open?`, `event?` | 扉（4 章） |
| `chest` | `contents`, `event?` | 宝箱（1 度だけ。中身は 5 章） |
| `loot` | `contents` | 置いてある物。触れると 1 度だけ手に入る（遺物・素材・セル） |
| `breakable` | `size`, `breaksWith`, `toughness?`, `persist?` | ひび割れた壁（ドリルで壊す。壊すと戻らない）。`"persist": false` なら壊れた状態をセーブしない（ボス部屋の壊れる柱：やり直しで元に戻る） |
| `beacon` | `flag?`, `event?` | セーブビーコン：HP・武器エネルギー全回復、セーブ、**やられたとき戻る場所** |
| `npc` | `name`, `talk` か `event` | 住人。調べると会話（2 回目以降は `<talk>.again` があればそれ）。`id` が `npc_yana` ならヤーナのモデルが出る |
| `terminal` | `event`, `prompt?` | 調べるとイベントが走る端末・看板・店の窓口 |
| `sign` | `text`, `pos`, `size?`, `color?` | 見た目だけの看板・名札（その高さに文字が浮く）。建物の名前・訓練場の目印に |
| `decor` | `pos`（底の中心）, `size`, `color?`, `yaw?` | 当たり判定のない遠景の箱（`when` で出し入れできる）。章末の地平線のカランの影に使った |
| `switch` | `mode`, `radius?`, `timer?`, `toggle?`, `cond?` | スイッチ。`shoot`＝撃つと入る（動力の球・弁の輪。`pos` は球の中心の高さ）／`interact`＝調べると入る。入るとフラグ `switch.<id>`。`timer` 秒で切れる |
| `mover` | `size`, `move` か `to`, `speed`, `mode`, `cond`, `wait?` | 動く足場・ピストン・リフト（下記） |

### 扉・近道

```json
{ "type": "door", "id": "ch1.r10.door", "pos": [0,0,12.2], "yaw": 0, "size": [4,4,0.5],
  "lock": { "item": "key.valve" }, "consume": "key.valve", "text": "鍵が要る" }
```

- `lock`：条件（4 章）。省略すると鍵なし。
- `opens`：`interact`（調べて開ける。既定）／`auto`（`lock` の条件が満ちたら勝手に開く。「動力が通ると開く扉」）。
- `side`：`front`（扉の正面＝ローカル +Z 側からだけ開けられる）／`back`／`any`。**近道の「内側から開ける」**は、内側に向けた扉に `side` を指定し、開けた扉は `door.<id>` フラグで残る（部屋を出入りしても開いたまま）。
- 開いた扉はセーブされる（フラグ `door.<id>`）。イベントからは `{"open": "id"}` / `{"close": "id"}`。
- `"open": true`＝最初から開いている（戦闘の部屋の「閉じ込め」は、イベントで `close` し、倒したら `open`）。

### 動く足場（動力を流す仕掛け B3）

```json
{ "type": "switch", "id": "ch1.r12.s1", "pos": [-6,1.5,12], "mode": "shoot" },
{ "type": "switch", "id": "ch1.r12.s2", "pos": [6,1.5,12], "mode": "shoot" },
{ "type": "mover",  "id": "ch1.r12.piston", "pos": [0,0,9], "size": [5,0.5,5], "move": [0,4,0],
  "speed": 2.5, "mode": "toggle", "cond": { "all": ["switch.ch1.r12.s1", "switch.ch1.r12.s2"] } }
```

- `pos`＝足場の底の中心（始点）。終点は `move`（始点からの差）か `to`（座標）。
- `mode`：`toggle`（`cond` が真なら終点、偽なら始点へ。動力の足場）／`pingpong`（`cond` が真の間ずっと往復。端で `wait` 秒止まる。ピストン）／`ride`（上に乗ると終点へ、降りると戻る。リフト）。
- 乗っているハルは一緒に運ばれる。**切り替わり（動力が通ったとき）はトリガーの `on: "flag"` でカメラを足場へ向ける**とよい（`sample.gym` の `gym_power`）。
- 動力が通った状態は `ch1.drive_powered` のようなフラグにして、ほかの部屋の扉の条件にも使える。
- セーブから戻ると、条件に合った位置から始まる。

### 宝箱・拾い物の中身（contents / give）

`{ "cells": 200, "item": "chip.charge", "items": ["key.x"], "materials": { "scrap": 3 }, "relics": ["relic.old_gear"], "heals": 1, "gp": 10, "mark": "降下許可", "lifecore": true }`（すべて任意）。`lifecore` は最大 HP +20（ライフコア。セーブされる）。
アイテム・素材・遺物の名前と売値は `items.json`（`name`, `kind`, `sell`）。無いと id がそのまま表示される。

## 4. 条件（cond）とフラグ

フラグは世界で 1 つの名前の表（真偽）。イベントで立て、条件で読む。**セーブされる。**

```
"ch1.drive_powered"                        文字列＝そのフラグが立っている
{ "flag": "x" }  { "item": "key.a" }  { "cells": 200 }  { "mark": "降下許可" }  { "material": "scrap", "n": 3 }
{ "cleared": "グループ名" }
{ "not": 条件 }  { "all": [条件…] }  { "any": [条件…] }  配列＝all
```

ゲームが自動で立てるフラグ：`chest.<id>`（開けた）、`broken.<id>`（壊した）、`door.<id>`（開いた）、`switch.<id>`（入っている）、`got.<id>`（拾った）、`beacon.<id>`（使った）、`defeated.<id>`（`once` の敵を倒した）、`cleared.<グループ>`（グループを全滅させた）、`visited.<部屋>`、`trigger.<id>`（1 回きりのトリガーが走った）、`<talk>.done`（会話した）、`crafted.<レシピ>`、`request.<依頼>`。
ボス「閂」を倒すと `ch1.boss_defeated`。第1章のフラグ名は `30_レベルデザイン設計.md` 4.6 の表（`ch1.*`）に合わせる。

## 5. 敵

```json
{ "type": "sentry", "pos": [4,0,6], "yaw": 180, "id": "r09.s1", "group": "r09_wave1" }
{ "type": "kannuki", "pos": [0,0,0], "id": "kannuki", "unless": "ch1.boss_defeated" }
```

- 型：`sentry`・`charger`・`mini`・`shield`・`floater`・`kannuki`。
- `group`：同じ名前の敵が全滅すると `cleared.<group>` が立つ（トリガーの `on: "cleared"`、イベントの `wait_until` に使う）。
- `once: true`（と `id`）：倒したら二度と出ない。ふつうの敵は部屋に入り直すと復活する。
- ボスは `unless: "ch1.boss_defeated"` で、倒したあとは出さない。やられたらボスは最初から。
- `"invulnerable": true`：倒せない敵（追跡の演出の歩哨型）。部屋を出れば消える。
- `"passive": true`：何もしない敵（動かず撃たない。`invulnerable` と組み合わせると練習用の的になる）。
- 戦闘の部屋の作り方：敵を `enemies` に `group` と `"unless": "ch1.<部屋>.cleared"` で置き、「全滅したら次の波」はトリガー `{ "on": "flag", "cond": { "all": [ { "cleared": "グループ" }, { "not": "ch1.<部屋>.cleared" } ] }, "event": …, "persist": false }`。最後の波のあとにイベントで `ch1.<部屋>.cleared` を立てる。途中でやられて部屋が作り直されても、`persist: false` のトリガーと `cleared` の旗はやり直しで元に戻る。

## 6. トリガーとイベント

```json
{ "id": "enter",  "pos": [0,0,3], "size": [4,3,2], "event": "ch1.r04.enter" }              範囲に入る
{ "id": "powered", "on": "flag", "cond": "ch1.drive_powered", "event": "ch1.r12.powered" }  条件が真になる
{ "id": "wave1",  "on": "cleared", "group": "r09_wave1", "event": "ch1.r09.wave2" }         グループ全滅
```

`once`（既定 true）、`cond`（範囲に入ったとき、さらに条件を付ける）。1 回きりのものはセーブされ、二度と走らない。`"persist": false` を付けると「走った」ことをセーブしない（部屋に入り直すとまた走る。戦闘の部屋・ボス部屋の入口の会話に）。

イベントは手順の並び。1 つの手順に主となるキー 1 つ。

| 手順 | 内容 |
|------|------|
| `{"say": "会話id"}` | 会話を出す（終わるまで待つ） |
| `{"flag": "x"}` / `{"clear": "x"}` | フラグを立てる／消す |
| `{"give": { contents の形 }}` | 渡す（セル・アイテム・素材・遺物・補修パック・印） |
| `{"wait": 秒}` / `{"wait_until": 条件}` | 待つ／条件が真になるまで待つ（敵の全滅待ちなど） |
| `{"message": "文"}` / `{"objective": "文"}` / `{"sfx": "id"}` / `{"music": "id"}` | 通知／目的／効果音／音楽。音楽の既定は部屋の `mood`（遺構＝`bgm_ruins`、屋外・屋内＝昼は `bgm_town_day`・`ch1.night` で `bgm_town_night`）とボス戦（`bgm_boss`）から自動で決まる。`music` 手順は上書き：曲の ID（`bgm_end` は 1 回だけ鳴る）、`"none"` で無音、`"auto"` で自動へ戻す。部屋を移ると上書きは解ける。部屋に `"music": "id"` を書けばその部屋の既定の曲になる |
| `{"if": 条件, "then": […], "else": […]}` | 分岐 |
| `{"event": "id"}` | 別のイベントを呼ぶ |
| `{"open": "扉id"}` / `{"close": "扉id"}` | 扉を開ける／閉める |
| `{"spawn": [敵の指定…]}` | 敵を出す（`pos` か `at`、`group`） |
| `{"boss": "敵id"}` | その敵の戦闘を始める |
| `{"go": {"room": "r05", "spawn": "start"}}` | 別の部屋へ移す（崩落で B2 へ落ちる、など。`autosave: true` でオートセーブ） |
| `{"teleport": {"at": "目印"}}` | 同じ部屋の中で移す |
| `{"camera": {"pos": [x,y,z], "height": 1.5, "time": 2.0}}` | カメラをその点へ向ける（`time` 秒、待つ）。`{"camera": {}}` で戻す。`"eye": [x,y,z]` を足すと、カメラを 1 秒かけてその場所へ移して `pos` を見る（部屋の外から見せる：下段の踊り場の「見下ろす」でオルドの脚。2026-10-16）。`"wait": false` で待たない。`"side": true` を足すと、ハルが部屋の真ん中の線（x = 0）の反対側にいるとき `pos` と `eye` を左右に映す（左右対称の部屋で、真ん中の柱の陰にハルが隠れないように。炉心の「ch1.node」） |
| `{"fx": "frame_fit", "part": "core"}` / `{"fx": "node_memory", "pos": [x,y,z], "height": 3.0}` | 見た目の合図（遊びは変えない。待たない）。`frame_fit`：その部位（`core`・`arm`・`legs`）のフレームの装着のエフェクト（その力のフラグより後に置く。台本の途中で付いた部品は、合図か台本の終わりまで隠れている）。`node_memory`：その位置（ノード）からナゴミへ記憶の光が流れ込む。`docs/art_orders/W2_エフェクトの結果.md` 8 章 |
| `{"freeze": true/false}` | プレイヤーの操作を止める／戻す（演出中。会話中は自動で止まる） |
| `{"mark": "降下許可"}` | 回収屋の印を上げる（見習い→降下許可→銅→銀→金→一人前→白磁） |
| `{"shop": "id"}` / `{"workshop": "id"}` / `{"guild": "id"}` | 店・工房・ギルドの画面を開く（`economy.json`。画面は段階 D で作り込む） |

## 7. 会話

```json
"ch1.yana.debt": { "lines": [
  { "who": "ヤーナ", "face": "smirk", "text": "来たね、坊主。ツケの話だよ。" },
  { "who": "ヤーナ", "face": "normal", "text": "どうする？", "choices": [
      { "text": "払う", "set": "ch1.debt_paid", "event": "ch1.debt.pay" },
      { "text": "待ってほしい", "say": "ch1.yana.debt_wait" } ] },
  { "action": "flag", "flag": "ch1.debt_scene" },
  { "action": "give_item", "item": "special.drill" } ] }
```

- 行：`who`（名前）、`face`（表情）、`text`。
- 顔のアイコン（会話の窓の左の枠）：Codex の会話の顔の絵を `tools/face_icons.py` が人ごとに切り出した物（`godot/assets/ui/faces/<絵の名前>_<表情>.png`、256px）。
  絵があるのは ハル（9 つ）・ヤーナ（8）・ナゴミ（8）・バートン・ニコ・トルーデ（4）・雑貨屋の店主・ジャンク屋（2）。話し手の名前と絵の名前の対応、
  絵の無い表情の読み替え（例：バートンの serious → normal、ナゴミの smile → happy）は `Hud.FACE_ID`・`Hud.FACE_ALIAS`。読み替えにも無い表情は normal。
  絵の無い人（町の住人の多く、ダグ・ハイナル）は名前の頭文字の丸。ハルは、フレームと適合する（`ch1.frame_fitted`）までは右肩の板と肩ひもの無い顔（W1-01c）。
  表情の名前：normal・smile・laugh・smirk・surprised・serious・sad・angry・troubled（ナゴミはほかに analyzing・happy・joking・confused・warning・dormant）。
- `choices`（少なめに）：出し終えたあと上下で選び、決定で確定。`set`（フラグ）、`event`（イベントを走らせる）、`say`（続きの会話）のどれでも。
- 行と行のあいだに `{ "action": "flag" | "give_item" | "objective" | "event" | "give", … }` を入れられる。
- 住人の会話は `talk` に `"<id>"` を書き、2 回目以降の別の台詞は `"<id>.again"` を作る。

## 9. セーブとやられたとき

- **ビーコン**：HP・武器エネルギーを回復し、セーブ（手動の枠）し、**やられたとき戻る場所**になる。エリアを移るたびにオートセーブ（別の枠）。「つづきから」は新しいほうを読む。
- やられたら、最後に使ったビーコン（無ければ最初の場所）から再開。開けた宝箱・壊した壁・開いた扉・倒したボス・立てたフラグはそのまま。ほかの部屋なら、その部屋は作り直される（敵は復活）。
- セーブには、フラグ全部・持ち物・セル・素材・遺物・印・依頼・今の部屋と位置・戻る場所が入る。形式は v2（v1 も読める）。

## 14. 部屋の見た目：キット（`kit`）・飾り（`dress`）・`skin`・`hide`

灰色の箱の部屋に、絵（Codex の部品のシート）から作った材質と部品をかぶせる。**見た目だけ**で、当たり判定・目印・出口・トリガー・置く物は何も変わらない（当たり判定はいつも geometry から作る）。
手で触れる大きさの飾り（箱・樽・鉢植え…）の当たり判定は、部屋の JSON を書く道具が飾りの `"solid"` から描かない形（geometry）を作って足す（14.3）。
`"kit"` も `"dress"` も無い部屋は、今までどおり灰色の格子で描く。作るのは `scripts/view/room_kit.gd`（`RoomView.build` から呼ぶ）、テストは `tests/test_kit.gd`。

### 14.1 部屋に書くこと

| 場所 | 項目 | 内容 |
|------|------|------|
| 部屋 | `"kit": "ruins_b1"` | `content/kits/<id>.json` を読み、geometry の面に材質を貼る（14.2） |
| 部屋 | `"dress": [ … ]` | 飾りの部品（`res://assets/kit/<part>.glb`）を並べる（14.3） |
| 部屋 | `"ordo": {"pos": [x,y,z], "back": "town/ordo_back", "ground": true}` | 町の下の巡礼機オルド（14.5）。`pos` は部屋の座標でのオルドの原点（背の歩行面の真ん中、+Z が船首）。体は部屋と一緒に止まり、120 m 下の砂の床が流れる。`back` は背の上の遠くの町の部品（オルドと同じ 3 つの面で描く）、`"ground": false` で砂の床なし、`"landing": false` でオルドのリフトの踊り場（部品 `lift_landing`）を隠す（部屋が同じ形の飾り `town/ordo_landing` を同じ pos に置くとき） |
| 形（geometry の 1 つ） | `"skin": "metal"` | その形の面を全部、キットの面 `metal` にする。`{"floor": "sand", "wall": "plate"}` なら面の向きごとに替える（`floor`・`wall`・`ceiling`） |
| 形 | `"hide": true` | 描かない（当たり判定は残る）。飾りの部品がその形の代わりに見えるとき |
| 形 | `"trim": false` | その形の壁の縁取り（幅木・笠木）を付けない |
| 形 | `"dress": 番号` | 飾りの `"solid"` から道具が作った形（その飾りの dress の番号）。手で書かない（書き直すたびに作り直す） |
| 形 | `"cam": false` | 体だけを止める形（`Phys.PROP`）。キャラクターの体は止まり、上に立てるが、カメラの壁よけ・弾・照準の線は通る（細い柱・頭の上の張り出し） |
| 置く物（`door`） | `"part": "town/gate_door"` | 扉の箱と灯の帯の代わりに、キットの部品で描く（原点 = 扉の箱の下の中心、正面 +Z。開くと部品ごと床へ沈む。`PropsView`） |
| 置く物（`terminal`） | `"hide": true` | 端末の箱と光る画面を描かない。飾りが同じ所に物を置くとき（ベッドの横の台・作業台の万力・望遠鏡・依頼板の書見台・リフトの操作盤）。端末の当たり判定（0.8×1.2×0.6 の箱）はそのまま |

```json
 "light": {"ruin_b1": {"ambient_color": "#b49a78", "ambient_energy": 0.55}},
 "surfaces": { "floor": { "albedo": "res://assets/kit/tex/ruins_ancient_floor.jpg", "uv_m": 6, "color": "#f4ece0", "roughness": 0.8 }, … },
 "materials": { "ivory": { … }, "graphite": { … }, "amber": { "color": "#ffbc52", "emission": {"color": "#ffbc52", "energy": 4} }, … }
}
```

- `dress_shadows`：飾りが影を落とすか（既定）。天井のある屋内（遺構）は太陽が入らないので false にする（影の描画を省く）。
- `auto`：`skin` の無い面の振り分け。上向き（法線の y > `up`）は `floor`、下向きは `ceiling`、ほかは `wall` の面の名前を使う。
- `trim`：縦の四角い面のうち、面の名前が `on` にあるものの下（高さ `base` m）と上（`top` m）に、`out` m 出た帯（面 `surface`）を付ける。低い面（`base + top + 0.2` 未満）は上の帯だけ。
- `surfaces`：面の名前 → 材質。`materials`：部品（GLB）の材質の名前 → 材質（同じ名前の材質を、部屋をまたいで共有の 1 つに置き換える。無い名前は GLB の色のまま）。
- 材質の項目：`albedo`（絵。1 枚 = `uv_m` m 四方）、`color`（掛ける色）、`roughness`、`metallic`、`macro`（0〜1。別の縮尺で同じ絵を重ね、繰り返しを目立たなくする）、
  `tint_mix`（0〜1。形の `tint` を掛ける）、`seams`（`{"every": [横 m, 縦 m], "width": m, "color"}`：板の継ぎ目の線。ワールドの格子にそろう）、`emission`（`{"color", "energy"}`：発光）。
- `light`：部屋の雰囲気（`mood`）ごとの光の上書き。`{"ruin_b1": {"ambient_color": "#b49a78", "ambient_energy": 0.55}}`。項目は `ambient_color`・`ambient_energy`・`sun_energy`・`sun_color`・`fog_color`・`sky_energy`・`saturation`（色の鮮やかさ）。
  `sky`：雰囲気ごとの遠景の空の絵（`{"day": "res://…jpg"}`、町のキット）。どちらも `EnvironmentSetup.apply_sky`（`main._apply_mood` から）。
- `tex_strength`（0〜1）：絵の模様の強さ（絵の平均の色は保つ）。黒鉛の擦り目のような強すぎる模様を弱める。絵は VRAM 圧縮・ミップマップありで取り込む（`.import` の `compress/mode=2`・`mipmaps/generate=true`。平均の色をミップマップから取る）。
- 光の筋の材質：`{"blend": "add", "color", "strength", "fade_m"}`（`kit_glow.gdshader`。足し合わせの半透明、上から `fade_m` m で消える）。
- しみの材質：`{"blend": "mul", "color", "strength", "uv_m", "mottle"}`（`kit_stain.gdshader`。下の床・壁の上に、color を暗くした色を半透明で重ねる。
  光と影は下の面と同じに受ける。名前は前の作り（下の色に掛ける `blend_mul`）のままだが、それはスマホ・ブラウザ版で黒く塗られたので、普通の半透明にした。
  汚れの置き場所の部品 `ruins/stain_*` に使う。2026-10-15、`43_遺構の見た目.md` 2.4・3 章）。
  **決まり：`blend_mul`（掛け算の半透明）は使わない**（`gl_compatibility` で黒くなる。町の汚れの斑 `"blend": "decal"` も同じ理由で普通の半透明）。
- `near_fade`：`[消える距離, 見える距離]`（m）。カメラからその距離の内を 4×4 の網目で抜く（`kit_surface_fade.gdshader`）。当たり判定の無い飾りの部品の材質に付ける
  （町は `flat`・`metal`・`amber`、遺構は `ivory`・`graphite`・`brass`・`cloth`・`grate`・`dark`・`sand`・`amber`。どれも `[0.8, 1.5]`）。日よけ・柱・灯・壁の板がカメラの前を塞がない。
  大きな建物の面（町の `shell`）と部屋の面（`surfaces`）には付けない（近づいたときに中が透けるため）。網目は `discard` を使うので、スマホ・ブラウザ版（`gl_compatibility`）では付けない。
- 面の UV はワールドのメートル：床・天井は (x, z)、壁は (壁に沿った長さ, 高さ)。だから 2 m の格子の継ぎ目は、どの部屋でも格子の線にそろう。
- `detail`：汚れ・傷みの層（14.2.1）。

#### 14.2.1 汚れ・傷みの層（`detail`）

面（`surfaces`）にも部品の材質（`materials`）にも、汚れ・傷みの層を 4 つまで重ねられる。写真の色は使わない：CC0 の写真から取り出した「型」（汚れの形）を
1 本のしきい値で切り、その内側を**パレットの色で平らに塗る**。型はなめらかな山と谷の形なので、近くで見ても縁のはっきりした平らな斑になり、写真の粒は出ない。
`detail` の無い材質は、前と同じシェーダー（`kit_surface.gdshader`）のまま（見た目も重さも変わらない）。層のある材質は `kit_surface_detail.gdshader`
（`near_fade` もあれば `kit_surface_detail_fade.gdshader`）。中身は `assets/shaders/kit_detail.gdshaderinc`、値を入れるのは `RoomKit._set_detail`。

```json
"wall": {"albedo": "res://assets/kit/tex/ruins_aged_ivory.jpg", "uv_m": 4.0, "color": "#f3ead8",
         "seams": {"every": [2.0, 1.333], "width": 0.06, "color": "#47463f"},
         "detail": [
          {"mask": "grime", "uv_m": 3.0, "cover": 0.6, "seam": [0.03, 0.3], "color": "#a07a5e", "mode": "multiply", "amount": 0.7},
          {"mask": "streaks", "uv_m": [2.0, 3.0], "cover": 0.5, "top": [0.0, 2.0], "color": "#9b5a3c", "amount": 0.55},
          {"mask": "grime", "uv_m": 2.5, "cover": 0.9, "feet": [0.3, 1.3], "color": "#9a6a4e", "mode": "multiply", "amount": 0.75},
          {"mask": "chips", "uv_m": 1.6, "cover": 0.22, "seam": [0.04, 0.35], "color": "#6a5646", "amount": 0.9}]}
```

| 項目 | 内容（既定） |
|------|------|
| `mask` | 型：`grime`（大きな汚れの斑）・`chips`（小さな欠け）・`mottle`（しっくいのむら）・`streaks`（縦の筋。さび・雨だれ）（`grime`） |
| `color`・`amount` | 塗る色（パレットの色）と強さ 0〜1（`#6b5444`・0.8） |
| `mode` | `paint`：色で塗る（下の絵が隠れる。砂・ほこり・欠け）／`multiply`：色を掛ける（下の絵の模様・継ぎ目が残る。汚れ・しみ）（`paint`） |
| `cover` | 覆う割合 0〜1。型の値は 0〜1 に均してあるので、`0.3` ならちょうど面の 3 割が斑になる（0.3） |
| `edge` | 縁の幅（型の値で）。小さいほどはっきりした縁。むらは 0.06〜0.08、ほかは 0.03〜0.05（0.03） |
| `uv_m` | 型の 1 枚の大きさ（m）。`[横, 縦]` で縦長にもできる。層ごとに型の位置をずらす（`offset` で指定も可）（2） |
| `on` | 付ける面：`all`・`floor`（上向き）・`wall`（縦）・`ceiling`（下向き）（`all`。`feet`・`top` があれば `wall`） |
| `feet` | 縦の面の足元：`[濃い高さ, 消える高さ]`（m）。形・部品の下の端からの高さ（壁の足元・箱の下・建物の足元の汚れ） |
| `top` | 縦の面の上の端から：`[濃い深さ, 消える深さ]`（m）。形・部品の上の端からの深さ（軒下・器具の下から垂れる筋） |
| `seam` | 板の継ぎ目（その材質の `seams` の格子）から：`[濃い距離, 消える距離]`（m）。継ぎ目の近くの傷み・欠け |
| `gate` | `{"cover": 0.5, "uv_m": 9}`：大きな縮尺の汚れの斑（`grime` の型）の中だけに出す。一面に同じ斑が散って模様に見えるのを防ぐ |

- 置き場所（`on`・`feet`・`top`・`seam`・`gate`）は**覆う割合に掛かる**。足元から離れるほど斑が細って消えていき、縁ははっきりしたまま（ぼかしの霧にならない）。
- 足元・上の端の高さは、面の UV2（`RoomKit` が付ける：x = 下の端からの高さ、y = 上の端までの深さ）。部屋の面は形の箱ごと（部屋の箱 `shell` は床の上の面から
  天井の下の面まで）、部品は部品の全体の高さで測る。だから建物の部品の `top` は屋根の軒の下、`feet` は部品の置いてある床。
- 遠く（型の 1 画素が画面の 3〜8 画素より細かい所）では、斑の形の代わりに覆う割合の平均の濃さで塗る（縮小した型はならされて、しきい値を越えなくなり、汚れが消えるため）。
- 型の絵（`tools/grime_masks.py` が `build/blenderkit` の CC0 の写真から作る。出所は `assets/kit/grime/SOURCES.json`）：
  `assets/kit/grime/masks.png`（512 px。RGB = `grime`、A = `chips`）と `masks2.png`（256 px。RGB = `mottle`、A = `streaks`）。
  VRAM 圧縮・ミップマップあり（PC は BC3、スマホは ETC2）。1 枚に型を 2 つ（白黒の RGB と A）だけ入れる。RGB に別々の型を 3 つ入れると、圧縮で切った縁が 4×4 画素の段々に崩れた。
  ブラウザ版の大きさは 2 枚で +0.83 MB（PC 用とスマホ用の 2 形式）。材質の `detail_tex`・`detail_tex2` で別の絵にもできる。
- 重さ：描画の数・三角形は変わらない（シェーダーの中だけ）。1 画素あたり、層 1 つにつき型の読み出し 1〜2 回。
- スマホ・ブラウザ版（`gl_compatibility`）でも同じシェーダー・同じ値で描く。ただしこの描き方は、影を落とす光（太陽・影つきのスポット）を別の回で描いて、
  トーンマップと sRGB に直した色を画面に足す（Godot 4.5）。光の当たる床が Forward+ より明るく白っぽく出て、汚れも薄く見えた。
  そこで、この描き方では太陽の強さを `EnvironmentSetup.COMPAT_SHADOW_LIGHT`（0.4）倍にし（物だけを照らす光にして、空の太陽の円盤は
  空だけを照らす別の光 `SkySun` で前の強さのまま描く）、部品の影つきの光（14.3 の `light` の `shadow`）は影なしにする。
- **場所ごとの汚れ**（2026-10-15）：面・部品の材質はキットで 1 つなので、同じ部屋の中の「汚れるべき所」は次の 2 つで変える。
  - **汚れの斑の板**：材質 `{"blend": "decal", "color", "amount", "cover", "edge", "uv_m", "falloff": [内, 外], "fade_far": 70, "roughness"}`
    （`kit_decal.gdshader`）。町の部品 `town/grime_patch`（材質 `grime_decal`）・`town/oil_patch`（`oil_decal`、油じみ）を床の 3 cm 上に置き、`scale` で広さを決める
    （`dress_town.dirt(d, x, z, 幅, 奥行き)`）。斑の形は汚れの型をワールドの (x, z) で読み、板の真ん中ほど覆う割合が大きく、縁で 0 になる（板の四角は見えない）。
    床と同じ向きの半透明で、光と影を受ける。掛け算の半透明（`blend_mul`）は、スマホ・ブラウザ版（`gl_compatibility`）で板が真っ黒に塗られたので使わない。
    戸口・階段の足元・路地・作業台のまわり・リフトの前・残骸のまわりに置く（14.7）。部品 1 種につき描画 1 回（部屋じゅうの板を 1 つの MultiMesh で）。
  - **キットの受け継ぎ**：キットの JSON に `"base": "town"` と `"detail_scale": 0.55`（か `{"amount": 1.2, "cover": 1.25}`）を書くと、元のキットの全部を受け継ぎ、
    元の面・材質の汚れの層の強さ（と覆う割合）にその数を掛ける（1 まで。この JSON に書いた面・材質には掛けない）。`town_tidy`（町長の家・上段）・`town_worn`（工房）。
    部屋の `"kit"` を替えるだけ（`RoomKit.inherit`）。テストは `test_kit_inherit_and_decal`。
- 確かめ方：`tools/godot.sh shot --resolution 1280x720 -- --demo=<出力> --stage_shots`（町は `--town_shots`）。スマホの寸法は `--resolution 844x390` と `--stage_view=r02_entry`・
  `--town_view=market`・`--touch`、ブラウザ版の描き方は `tools/godot.sh shot` に `--rendering-driver opengl3 --rendering-method gl_compatibility` を足す。
  テストは `tests/test_kit.gd` の `test_kit_detail_materials`（層の有る・無い材質、キットの材質、UV2）。

#### 14.2.2 飾りの動き（`sway`・`flow`・`emitters`、2026-10-19）

止まっていた町と遺構の飾りを少し動かす（場所が生きて見えるように）。風で揺れる布（旗・吹き流し・小旗の綱・洗濯物・垂れ幕・日よけと露店の垂れ）、
遺構の垂れたケーブル（ゆっくりした振り子）、落砂の流れ（下へ流れる模様と、着く所の砂ぼこり）、蒸気（外へ流れる濃淡と、数秒ごとの吹き出しの粒）。
**どれも見た目だけ**：時刻は描画の時計 `TIME`（シェーダー）と Fx の刻み（粒）だけで、ゲームの中身（`GameSim`）は読まない・変えない
（決まった刻みのテスト・見本の通しは前と同じ）。

**どこを動かすか＝部品の頂点の色のアルファ**（1 − 動きの重み。0 = 竿・綱・棒・留め金の側の留まった端、1 = いちばん動く自由な端）。Blender の書き出しが付ける。
材質を分けると部品ごとに描画が 1 回増えるので、材質は前のまま（町は `flat`・`metal`）で、頂点ごとに選ぶ。重みの無い GLB と部屋の面はアルファ 1（動かない）。

- 町（`tools/blender/kit/town_geo.py`）：形に重みを付ける `sway(形, fn)`、吊った布の `hang(上の端の y, 長さ, 上限)`、両端で留まった綱と吊った布の
  `sagging(x0, x1, y, 垂れ, 長さ)`、まとめて付ける `Part.mark()`・`sway_since()`。**重みは位置だけで決める**（同じ所の頂点は同じ重み：布の表と裏・柄の板・
  洗濯ばさみが一緒に動き、面が裂けない）。組の部品（`place`）に入れても付いたままなので、`lower_set`・`terrace_*`・`lower_block_*` などの中の日よけ・垂れ幕・
  旗・洗濯物も動く。重みの上限：旗・吹き流し・洗濯物・小旗の自由な端 1、竿の幟 0.6、日よけと露店・天幕の前の垂れ 0.5（`town_parts.SWAY_DROP`）、
  壁に沿う垂れ幕・壁掛け・布札 0.4（`SWAY_WALL`：壁から 4〜5 cm で、揺れはいちばん大きくても 2 cm ほどなので、押されても壁に入らない）、枠に張った帆布の真ん中 0.18（`SWAY_CANVAS`。縁は 0）、
  吊った乾物・吊り札 0.3〜0.45。屋内（ギルドの垂れ幕）は 0（風が無い）。
- 遺構（`tools/blender/kit/geo.py`）：部品の `motion = fn(材質, 頂点)`（Blender の座標）。垂れたケーブル（留め金の高さから 1.25 m 下で 1。ケーブルと切れた芯だけ）、
  落砂の流れ（床の山の上の細い流れだけ 1）。`ruins_clutter.py` の `cable_hang`・`cable_hang_cut`・`sand_fall`・`sand_stream`。
- 書き出し：重みのある部品だけ頂点の色をアルファごと書き出す（町は `export_vertex_color='NAME'`。`'ACTIVE'` だと、頂点の色を絵に使う材質だけの部品で
  RGB だけになり重みが消えた）。重みの無い部品は前と同じ GLB（作り直してもバイトまで同じ）。

材質の項目（キットの JSON。`surfaces`・`materials` のどれにも書け、汚れの層・`near_fade` の**どの版とも一緒に使える**：動きのコードは
`assets/shaders/kit_motion.gdshaderinc` にあり、`kit_surface.gdshaderinc` がどの版でも読む。シェーダーの版は前のままで、値が 0 なら何もしない）：

| 項目 | 内容 |
|------|------|
| `sway` | 風で揺れる布・垂れたケーブル：`{"push": 0.035, "flutter": 0.03, "wave": 0.45, "gust": 0.8, "speed": 1.0, "wind": [0, 0, -1]}`。重み 1 の頂点の、突風で風下へ押す距離（m）・揺れの幅（m）・風下へ進む波（1 m あたりの山）・突風の強さ（0〜1）・速さの倍率・風の吹いていく向き（ワールド。水平にして使う） |
| `flow`（不透明の面） | 落砂の流れ：`{"speed": 2.6, "size": 0.25, "contrast": 0.5, "edge": 0.6}`。下へ流れる速さ（m/s）・模様の縦の大きさ（m）・明暗の幅・縁（面が横を向く所）のちらつき。重みのある所だけ |
| `flow`（`"blend": "add"`） | 蒸気：`{"speed": 0.9, "size": 0.45, "contrast": 0.7, "breath": 0.25}`。吹き出し口から外へ流れる濃淡・ゆっくりした強弱（`kit_glow.gdshader`）。蒸気だけの材質なので重みは使わない |
| `emitters`（キットの項目） | 部品 → 粒の出所：`{"ruins/b2_steam": {"kind": "steam", "at": [0, 0, 0], "dir": [0, -1, 0], "every": [3.0, 5.5]}, "ruins/sand_fall": {"kind": "dust", "at": [0, 0.26, 0], "every": [0.35, 0.8]}}`。部品の中の位置・向き、間隔（秒、短い〜長い）。`kind` は `dust`（砂ぼこり）・`steam`（蒸気） |

- 今の値：町（`town`。`town_tidy`・`town_worn` も受け継ぐ）は `flat`・`metal` に `sway`。**風は船首（+Z）から吹き、風下は -Z**（町はオルドの背で前へ歩く。
  部屋の座標はオルドと同じ向き：`OrdoView`・14.5）。旗（`wind_flag`）は部品の +X が風下なので yaw 90 で置き、組の旗（訓練場・ギルドの屋上、展望台、
  夜明けの甲羅の見張りの台）も -Z へなびく形にした。遺構（`ruins_b1`〜`b4`）は `dark`・`brass` に `sway`（push 0・flutter 0.035・speed 0.8：ゆっくりした振り子）、
  `sand` に `flow`、B2 の `steam` に `flow`、`emitters` に落砂 2 種と蒸気。
- 揺れの中身（`kit_motion.gdshaderinc` の `kit_sway`）：風下 W と、それに直角の水平の向き S へ、場所で少しずつずれた 2 つのゆっくりした揺れ
  （3.3 秒と 4.6 秒。速さ 1 のとき）と、ときどき来る突風（平均 37 秒ごと、時間の 2 割ほど。風下へ流れていく帯）。重み 1 の頂点で平均 1.8 cm・最大 5 cm。
  場所ごとのずれは頂点のワールドの位置から（隣の布・旗とそろわない）。面の向き（法線）は変えない：波の傾きで傾けても画素はほとんど変わらず、
  スマホ・ブラウザ版の描き方（`gl_compatibility`）で、傾けた旗の吹き流しに一瞬だけ白い点が散った（同じ時刻で毎回。傾けない版では出ない）。
- 粒（`scripts/view/ambient_fx.gd` の `AmbientFx`）：Fx が毎刻み呼ぶ。部屋が変わると、キットの `emitters` と部屋の `dress` から出所を作り直す（`RoomKit.emitters`）。
  自分の乱数（部屋ごとの種）で出すので、Fx のほかのエフェクトの乱数の並びは変わらない。落砂の着く所の砂ぼこり（`Vfx.DUST`、0.35〜0.8 秒ごとに 1〜2 粒、
  横へ広がって 1〜1.6 秒で消える）、蒸気（`Vfx.SMOKE`、3〜5.5 秒ごとに 4〜6 粒の強い吹き出し、合間に細い粒。上がりながら広がって消える）。1 部屋 16 か所まで。
- 重さ：布・ケーブル・落砂の流れ・蒸気の濃淡はシェーダーの中だけで、描画の数・三角形は変わらない。粒は今ある層（DUST・SMOKE。普通の半透明）を使うので、
  出所のある部屋で多くて +2 回（その層がほかで出ていないとき）。測った数（`tools/audit_views_props_motion.json` の 14 向き、前 → 後）：
  町の中段のいちばん重い向き `pm_mid_high` は PC（Forward+ 1280×720）355 → 355 回・スマホ（`gl_compatibility` 844×390）385 → 385 回、下段・上段・中段の北の
  布の多い向きもすべて同じ（三角形は、風下へなびく形に作り直した組の旗の分だけ、上段の向きで +40）。遺構は粒の見える向きで +1〜2 回
  （r06 の南の壁 PC 93 → 95・スマホ 108 → 110、r02 の落砂 PC 141 → 142）、ケーブルだけの向きは同じ。
- 決まり：動かす物は材質ではなく頂点の色のアルファで選ぶ（描画を増やさない）。壁に沿う布は重み 0.4 まで、屋内は 0。`blend_mul` は使わない（どれも不透明の面の
  色・位置を変えるか、足し合わせ・普通の半透明）。時刻は `TIME` と Fx の刻みだけ（ゲームの中身から値を受けない）。
- 確かめ方：`tools/godot.sh shot --resolution 1280x720 --fixed-fps 60 -- --demo=<出力> --motion_shots`（`scripts/debug/motion_shots.gd`：旗・洗濯物・中段の北・

  `test_kit_motion_no_multiply_blend`（`tests/test_kit.gd`）、`test_ambient_fx_view_only`（`tests/test_vfx.gd`：粒が出る・ゲームの中身と Fx の乱数は変わらない）。

### 14.3 飾り（`dress`）

```json
"dress": [
 {"part": "ruins/b1_pillar", "pos": [-12, 0, -12]},
 {"part": "ruins/b1_wall", "pos": [-11, 0, -13], "yaw": 0, "count": 11, "step": [2, 0, 0]},
 {"part": "ruins/b1_lantern", "pos": [-12.5, 2.4, 0], "yaw": 90, "light": {"at": [0, 0, 0.3], "color": "#ffbc52", "range": 6, "energy": 1.2}}
]
```

| 項目 | 内容 |
|------|------|
| `part` | `res://assets/kit/<part>.glb`。無い部品は描かずに飛ばし、名前を警告に出す（部屋の `missing_parts` にも残る。落ちない） |
| `pos` | 部品の原点を置く位置（部品ごとの原点は 14.4） |
| `yaw` | 向き（度）。部品の正面（通路側）は yaw 0 で +Z、90 で +X |
| `rot` | `[x, y, z]`（度）。`yaw` の代わりに 3 軸で回す（倒れた物、縦の管など） |
| `scale` | 数か `[x, y, z]` |
| `count`・`step` | 同じ部品を `count` 個、ワールドの `step` [dx,dy,dz] ずつずらして並べる（壁・手すり・梁の列） |
| `shadow` | 影を落とすか（既定はキットの `dress_shadows`） |
| `light` | 部品に明かりを付ける：`{"at": 部品の中の位置, "color", "range", "energy"}`。`"type": "spot"` なら `"dir"`（部品の中の向き）・`"angle"`（度）・`"shadow"`（影。部屋に 1 つまで。スマホ・ブラウザ版の描き方では影なし：14.2.1）。明かりは重いので、部屋に数個まで |
| `solid` | 当たり判定を付ける（14.3.1）。`true` なら `tools/dress_solid.py` の表 `SOLID` の部品の形、`"<表の名前>"` なら表の別の行、`[[cx, cz, 幅 x, 奥行き z, 下の y, 上の y, yaw], …]` なら部品の中の箱を直接。ゲームは読まない（道具が geometry にする） |

- 同じ部品は 1 つの MultiMesh にまとめて描く（部品 1 種 × 材質の数だけの描画）。部品のメッシュと材質は 1 回だけ読む。毎フレームの処理は無い。
- 飾りそのものには当たり判定が無い。歩ける所に `solid` の無い飾りを置くのは、床の上の薄い物（格子・砂）や、壁の帯の内（遺構）・壁から 0.15 m 以内の物、
  綱・ひもだけにする。高い所の通路（`b1_walkway`）は跳んでも届かない高さに。

#### 14.3.1 飾りの当たり判定（`solid`）

前は飾りに当たり判定が無く、床に置いた箱・樽の中にハルが入り込み、頭だけ出して立てた（ハリボテに見えた。遺構 B1 の部屋の四隅の箱、整備通路の段の上の箱、
中段の露店の端の樽・食堂の角の木箱）。手で触れる大きさの物には `"solid": true` を付ける。

- 部屋の JSON を書く道具（`tools/dress_ruins.py`・`tools/dress_town.py`）が、`tools/dress_solid.py` の `SOLID`（部品の中の箱。寸法は部品を作る Blender の
  スクリプトから）を部品の `pos`・`yaw`・`scale`・`count`/`step` のとおりに置いた描かない形 `{"t": "box", …, "hide": true, "dress": <dress の番号>}` を
  geometry の終わりに足す。何度流しても同じ（前の `"dress"` つきの形は消して作り直す。手で書いた形の番号はずれない）。
- 置く形は軸にそろった箱だけ。部品・箱の向きが 90 度の倍数でなければ、回した広がりを囲む箱にする（斜めの箱の面と壁の間のくさび形のすき間に体が押し込まれると、
  床を抜けて沈んだ）。だから**当たり判定のある部品は 90 度の倍数から数度までしか回さない**（4 度で、囲む箱は面の真ん中で 0.04 m 外。
  前は 10〜40 度回した箱があり、見た目の箱の 0.25〜0.5 m 手前に見えない壁があった）。階段の形（`stairs`）は 90 度の倍数の向きで置ける。
- 丸い物（樽）は半径の四角い箱。組の部品（露店・天幕・工房と食堂の正面・壇・階段の手すり・北の段の擁壁）は、中の物ごとに箱を書く。
- **体だけの箱**（箱の印 `cam=False`、形の `"cam": false`）：細い柱（露店・天幕の柱、旗竿、外灯の柱、洗濯綱の柱）と胸壁の上の手すりは、柱の高さいっぱいの体だけの箱
  （カメラは当たり判定の箱の 0.3 m 手前に寄るので（14.6）、ふつうの箱にすると柱がハルの後ろを横切るたびにカメラが跳ねる）。
  前は細い柱を 1.2 m までの低い箱にしていて、跳んで乗ると柱の途中の宙に立てた。柱の上の端は柱の本当の上の端（そこに立つのは見た目どおり）。
- **乗れない柱**（`NOGO()`、形の `"nogo": true`、体だけ）：頭の上の張り出し（日よけ・巻き上げ帆布・吊り灯・雨戸・壁の上の太い管）と、露店の屋根・台の上の品・
  天幕の帆布の上。下の端は帆布の下の面に合わせて段にし（跳ぶと頭が当たる。前は帆布・灯の中を頭が抜けた）、上の端は近くの立てる所から跳んで届く高さより上にする
  （上に立てる箱にすると、上に乗って次の高い所へ行けてしまう。前は工具棚 → 給水塔 → 露店の屋根の描かない箱と登れ、屋根の上を歩くと靴が帆布の下へ抜けた）。
- **すき間をふさぐ**（`fill_gaps`）：飾りの箱と、壁・ほかの箱との間の 0.75 m（体の太さ 0.7 m）より狭いすき間は、低いほうの高さまで描かない箱でふさぐ
  （すき間の深さは、下の床・前にふさいだ箱から測る。浅い所はふさがない）。前は遺構 B1 の角の箱と壁の間（0.3〜0.6 m）・食堂の卓とベンチの間（0.33 m）に、
  上から歩いて下りた体が両側の角に引っかかって宙に浮き、立てず跳べず出られなくなった。ふさぐ箱が 0.3 m より広く、上の端が 3 m より低いと道具が警告を出す
  （見えない棚になる。置き方を直す：角の箱は壁の帯・角の柱にぴったり寄せ、食堂のベンチは卓の縁から 0.08 m、胸壁の前の大きな鉢植えは胸壁から 0.34 m）。
  高い所どうしの間（積んだ木箱と樽・頭の上の乗れない柱、手すりの端どうし、手すりと配管の端）も、体の太さより狭いと体の丸い底が挟まって宙に止まる。
  0.75 m 以上離すか、くっつけるか、体だけの箱でつなぐ（食堂の裏の樽は木箱の山の横に寄せ、木箱の山は日よけと窓の雨戸の柱から 0.75 m 以上。
  胸壁の上り口の背の高い外灯は胸壁の面から 0.9 m。南の角では東西の手すりと胸壁の手すりの端を、北東の角では手すりと配管の端をつなぐ）。
  出口・トリガー・目印の決まりの距離に入るすき間はふさがない（道具が知らせる）。
- **壁の帯**（遺構、箱の印 `wall=True`）：壁の部品（`b1_wall`・`b1_door`・`b1_corner`）は、壁の面から 0.36 m の描かない帯を当たり判定にする。部品の出っ張り
  （板・柱・金具・管・灯）は壁から 0.35 m（`ruins_b1.RELIEF`）までに収める。前は柱が 0.42〜0.53 m、角の柱が 0.65 m 出ていて、体の中心が壁から 0.35 m まで
  寄れたので、壁ぎわを歩くと体が柱・板の中に半分入った。帯は出口・トリガーの箱に、壁ぎわの 1.0 m までは掛かってよい（出口の口はふさがない）。
- **町の棟の面から出た物**：窓台と窓の枠（面から 0.15〜0.19 m、肩の高さ）・工房の入口の奥まりの内張り（口の側の面から 0.3 m）・南の階段の下の縦の管
  （壁から 0.29 m）も、面の前の帯・体だけの柱にする。前は壁ぎわを歩くと肩が窓台に入り、入口へ歩くと体が内張りに 0.3 m 入り、管を体が抜けた。
  歩ける所の横の低い窓は雨戸の無い窓（`window_flush`・`town_terrace._window_flush`。雨戸は 0.6 m 出て頭の高さまで下がる）。
  外灯は、柱の上の端・腕・灯を 1 つの体だけの箱にする（間に体の丸い底が落ちて宙に止まった）。
- 決まり（道具が確かめ、だめなら書かずに止まる。テストも同じ）：出口・トリガーの箱から 0.1 m、目印・チェックポイント・敵の出る所から 0.6 m、
  調べる物・拾う物・住人から 0.5 m 離す。ただし両辺が 4 m 以上のトリガー（広場などの「場所」。どこからでも歩いて入る）の中には、床の上の広がりが
  0.5 m より小さい箱（記念の柱の吊り灯の乗れない柱など）は立ててよい（`dress_solid.AREA`・`SMALL`）。整備通路の溝と、溝の縁から 1.5 m（着地・踏み切り・跳んでいる所）には、頭の届く高さに壁の帯より前へ出た箱を置かない
  （跳んでいる体が当たって止まり、溝に落ちる）。だから溝の縁の目印の灯は壁に付ける `b1_edge_lamp`（壁の帯の内。前は床に立つ灯の柱で、当たり判定が無く体が柱を抜けた）、
  壁の琥珀の灯は溝と溝の縁から 1.5 m の外に付ける。
- 前から同じ広さの描かない箱がある飾り（中段の木箱の山・ガラクタ、遺構 B1 の折れた柱）には付けない。
- テスト（`tests/test_kit.gd`）：`test_dress_solid_props`（solid の飾りに箱がある、箱・樽・鉢植えなどがどれも当たり判定の箱の中に立つ、決まりの距離、

### 14.6 ハリボテを作らない（見た目の点検）

飾りは当たり判定が無いので、正面の板だけ置くと、横・裏・上から見たときに奥が何も無い板（ハリボテ）になる。次を守る。
手で触れる大きさの物（箱・樽・鉢植え・ベンチ…）は `solid` で当たり判定を付ける（14.3.1。中に入り込めると、それもハリボテに見える）。

- 建物は箱（正面・側面・屋根・奥行き）で作る。壁の面に正面を貼るだけにしない。壁の端・切れ目（階段の口・路地）・建物の横と裏・屋根の上も、プレイヤーとカメラから見える所は作る。
- 見えている面は、当たり判定の面と同じ所に置く（見えない壁にぶつかる・壁の中に物が見える、を作らない）。当たり判定の箱を描かずに家の塊を見せるときは、その箱に `"hide": true`。
- 飾りの列は当たり判定の端で止める。壁の箱より先へ出た手すり・笠木・擁壁の板は、端から見ると宙に浮いた薄い板になる（例：東西の低い壁の手すりと擁壁は
  壁の箱の北の端 z=16 で止め、最後の 1 本は 6 m（`scale [0.75, 1, 1]`）。壁の端の面は角の柱 `parapet_corner` でふさぐ）。
- 当たり判定の無い見た目だけの塊（家・屋根）を、プレイヤーの届く縁（立てる面）の横に同じ高さで置かない。歩いて・跳んで乗ると落ちる。
  当たり判定を足さないなら、届く縁より 2.5 m 以上低くして（跳ぶ高さは 2.2 m）、縁の向こうの下の町に見せる（例：南の階段の両側の棟の屋根は、胸壁の上 1.2 m の横で -2.0 m、
  横の壁の上 3.0 m の横で 0.5 m、奥の壁の上 4.0 m の向こうで 1.5 m。家より上に出る壁の外の面には付け柱・帯・笠木を付けて、厚みのある壁に見せる）。
- カメラは当たり判定の箱にだけ当たり、箱の 0.3 m 手前より先へは行かない（`camera_rig.gd`。前は最短 1.2 m まで下がって壁の中に入った）。体だけの箱（`"cam": false`）には当たらない。
  壁が 1.2 m より近いと、カメラを 15 度ずつ上へ回して（75 度まで）頭の上から見る。当たり判定の無い飾りは、材質の `near_fade` でカメラの 0.8〜1.5 m の内を網目に消す（14.2）。
  それでも、当たり判定より外・上にある見た目だけの大きな塊（`shell`）にはカメラが入りうる。カメラが届く所（プレイヤーの立てる所から 5.5 m、跳んで 2.2 m 上）では、
  見た目だけの塊は当たり判定の上の面より下げるか、当たり判定の面から十分に引っ込める（例：北の路地は 9 m（横の壁の上）より上の家を |x| 8 まで下げる）。
- 出口の先を平らな壁のままにしない。出口（`exit`）の先の壁には門・扉を付けて、そこから先へ行けると見せる（例：南の階段の下の踊り場の奥に下の段への門。前は 9 m の壁だけで、近づくと部屋が変わった）。
- 落ちる所（当たり判定の無い下）：最後に立った高さより 0.8 m 下で、足の下（今の横の速さで 0.5 秒先まで）に奈落の高さ（y -30）まで何も無ければ、カメラは縁で止まって見下ろし、
  画面を暗くする（立った高さから 0.8 m で暗くし始め、4 m で真っ暗。`camera_rig.gd` の `FALL_*`）。直前の足場に戻ると、暗いうちにカメラも戻ってから明るくなる。
  だから部屋の下（床の裏・縦穴の外）や、見た目だけの下の町の床の裏は映らない。縁から見下ろす穴は底が見えない深さにする（遺構の `b1_pit` は 20 m）。
  穴を跳び越す・段を飛び降りる（下に床がある）ときは止めない。
- 片面の板（裏から見ると消える）は、見える側だけでなく裏から見えないかも確かめる。重なる 2 つの面は 2 cm 以上離す（ちらつき）。芯の箱と冠・金具の上の面を同じ高さにしない（14.4）。隣り合う家は正面と屋根の高さを少しずらす。
- 同じ平面で重なった同じ向きの面（ちらつき）は `tools/blender/kit/check_coplanar.py` で探す（bpy なし。`--room ch1_town.json:mid,ch1_ruins.json:r02,ch1_ruins.json:r03` で
  部屋に置いた形のまま、部品どうし・部品と地形の箱の重なりも。届かない側を向いた面・別の形に覆われた面・床に載った下向きの面は数えない）。
  部品の中の重なりは、書き出し（`town_geo.to_object`・`geo.to_blender`）が `separate` でほどく：重なった 2 つの面（5 mm 以内）の小さい方を、相手の面より 1.5 cm 外へ
  （その平面にある形の頂点ごと。箱なら面が伸びる）。5 mm は、スマホ・ブラウザ版の 24 bit の深さで 30 m 先の 2 mm が分けられないため。
  部品と地形の箱の重なり（胸壁の箱の上の面と笠木、台の箱と上の布、建物の箱の横の面と正面の端の柱、広場の床の板と天幕の足）は、置く部品の側で 2 cm 外へ出して直す。
  管（`town_parts.pipe_run`）の両端の継ぎ輪は管の端より 2 cm 外へ出して口をふさぐ（前は継ぎ輪のふたと管のふたが同じ面で、端がまだらにちらついた）。
- 当たり判定の無い飾りは、カメラの 0.8〜1.5 m の内で網目に消える（`near_fade`）。カメラの高さ（約 1.9 m）に届く物を、カメラが下がってくる部屋の角に置かない
