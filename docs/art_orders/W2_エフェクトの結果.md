## 1. 仕組み：粒の層（`Vfx`）

- 粒は 2 種類。`emit()`：寿命のある粒（位置・速さ・重力・空気の抵抗・床で跳ねて止まる・回転・大きさと明るさの変化を `Vfx` が進める）。
  `sprite()`／`streak()`：その刻みだけの板（弾の芯・溜めの輪・予兆の光・輪の線など、動く物に付く物。毎刻み置き直す）。
- 板の向きは 3 つ：カメラを向く板、変換のままの板（床の輪・斬撃の帯・溜めの輪）、軸に沿って伸びてカメラを向く筋（火花・弾・速さの筋）。
  シェーダーが粒ごとの値（`INSTANCE_CUSTOM`）で向きを決める。斬撃の帯はマスクの円弧の角度で「振り抜き」を見せる（拭き出し）。
- 層ごとに 1 つの MultiMesh。何粒・いくつのエフェクトが重なっても、描画の回数は使っている層の数しか増えない。空の層は隠す。層ごとに粒の上限がある（超えたら古い粒から消す）。
  粒の位置から毎刻み範囲（AABB）を作り直す（半透明の並びと、画面の外の層を描かないため）。
- **GPU の粒子（GPUParticles3D）は、Godot 4.5.1 の gl_compatibility でも描けた**（xvfb＋Mesa の OpenGL 4.5 で、MultiMesh の粒と並べて確かめた）。
  それでも使わなかった：エフェクトの数だけノードと描画が増える、弾や輪のように動く物に付く板を毎刻み置き直すのに向かない、時間の曲線を見本どおりに細かく決めたい。
  `CPUParticles3D` も同じ理由で使っていない（どちらも 1 つの放出に 1 回の描画）。
- 粒は GDScript で進める。上限は 14 層で合わせて約 1,000 粒。戦闘の重い場面でも数十〜百数十粒（5 章の物理の刻みの時間）。

### 1.1 層（マスクと混ぜ方）

混ぜ方は 2 つだけ：足し合わせ（`blend_add`、光）と普通の半透明（`blend_mix`、物と色の地）。掛け算（`blend_mul`）は使わない（42 章：gl_compatibility で黒くなる）。

| 層 | マスク | 混ぜ方 | 主な使い道 |
|----|--------|--------|-----------|
| SPARK | `spark`（窓 0.4 倍・38° 回して軸に合わせる） | 足し合わせ | 火花・速さの筋・削岩腕の軌跡 |
| GRAIN | `grain`（0.34 倍） | 足し合わせ | 光の粒・にじみ・弾の筋・輪の線 |
| GLINT | `glint`（0.2 倍） | 足し合わせ | 銃口・命中・撃破の閃き |
| RING | `shock_ring` | 足し合わせ | 溜めの輪・ドリルの輪・広がる輪・解析の輪 |
| SLASH | `slash` | 足し合わせ | 斬撃の帯の光の芯（拭き出し） |
| SLASH_MIX | `slash` | 半透明 | 斬撃の帯の琥珀の地（明るい床の上でも色が残る） |
| PILLAR | `pillar` | 足し合わせ | 光柱（ビーコン・宝箱・召喚の床口・封印・撃破の光） |

### 1.2 色と明るさ

- 環境の色調（AgX）は明るい色をくすませる。見本の琥珀 `#FFBC52` をそのまま渡すと画面では黄土色、珊瑚色 `#E26A4A` は鮭色に見えた。
  ゲームと同じ環境に色の板を並べて写し、**画面で見本の色に見える少し濃い色**を渡すことにした：琥珀 (1.0, 0.62, 0.16)、珊瑚色 (0.95, 0.30, 0.16)（`Fx.AMBER`・`Fx.CORAL`、`EnemyView.HAZARD`）。
- 明るさは `spec.md` の表の 0〜1 に 1.3 を掛けた強さ。足し合わせの光は明るい床の上では白っぽくなるので、
  色を見せたい所は「半透明の地の色（SLASH_MIX・SOFT・DOT）＋足し合わせの光の芯」にした（斬撃の帯・敵弾・予兆・溜め）。
- 大きな光（弱点・破断・撃破・突きの衝突・叩きつけの接地）だけ `Fx.flash_scale` を掛ける。どれも 0.1〜0.3 秒の短い光で、画面全体を光らせるものは無い。
  倍率は設定の「フラッシュの強さ」（8.1 節：標準 1.0 ／ 弱め 0.5 ／ 最小 0.2）。`Vfx.flash_scale` は、それ以外の足し合わせの明るい光の頭を同じ倍率で抑える。
- 色の決まり：ハル・ナゴミ・拾い物・ビーコンの光は琥珀。番機と閂の攻撃の予兆・敵弾・危険な範囲は珊瑚色。
  閂の錠前核は琥珀のまま（撃破のあとも光って残る）、過熱（第 3 段階）だけ真鍮の継手と床の外周が珊瑚色。

## 2. どこにつないだか

ゲームの中身が出している出来事と状態だけを使う（新しい出来事は出していない）。
8 章で、台本の見た目の合図（手順 `fx` → 出来事 `{type: "fx"}`。遊びは変えない）を 1 つだけ足した。

| 出来事・状態 | エフェクト |
|-------------|-----------|
| `game.shots` に新しい弾 | 銃口の光（ハルは琥珀、番機は珊瑚色）、溜め撃ちの輪、閂の破片射出の岩 |
| `game.shots` から消えた敵の弾 | 珊瑚色の着弾（同じ所の `hit`（装甲）は重ねない）。ハルに当たった弾は `playerHurt` が描く |
| `hit`（kind：normal／weak／armor） | 命中の 3 種。ドリルで削っている間は小さな削りの火花。壊せる壁を弾で撃ったら目印の不正解の反応 |
| `enemyDestroyed` | 番機の撃破（閂は `bossDefeated` の方） |
| `guardBroken` | 盾型の盾が崩れる |
| `wallBroken` | 壁が壊れる |
| `playerHurt` | 被弾（珊瑚色）。重い攻撃（`hurt_time`）は土煙も |
| `sfx`（id `heal`） | 回復 |
| `bossStuck`・`bossArmBroken`・`bossSummon`・`bossPhase`・`bossDefeated`（と閂の `dead_time`） | 突きの衝突・腕の破損と煙・呼び出しの床口・段階の輪・撃破の流れ |
| `saved`・`chestOpened`・`doorOpened`（id に seal） | ビーコンの起動・宝箱・封印の解除 |
| `player.attack`（技・時間）・`sword_hold`・`gun_charge`・`drilling`・`dash_time`・`invuln` | 斬撃の帯、光刃と銃の溜め、ドリル、ダッシュ、無敵の淡い光 |
| 敵の `state`・`state_time`（`windup`・`alert`・`stunned`・`attack`）、閂の `state`・`spin_r`・`wave_r`・`core_open`・`overheat`・`heat_state` | 警戒・予兆・激突・閂の技 |
| `lock_on.target`・`scan_progress()` | 解析の輪とナゴミからの光の帯、弱点への光の線 |
| `has_ability`（lock_on・sword・dash）が付いた・台本の `fx: frame_fit` | フレームの装着（胴・籠手・脚）。台本の途中で付いた部位は合図で出す（8.3 節） |
| 台本の `fx: node_memory`（ノードの位置つき） | ノードの記憶の取り込み |
| `game.pickups` から取られて消えた | 拾い物の吸い込み |
| `game.relics` が増えた（`chestOpened`・`lootTaken` の所、無ければハル） | 遺物を拾った光 |
| `game.chests`（開ける前）・`game.loot`（遺物）・`game.beacons` | 宝箱の縁と錠前、置いてある遺物の目印、ビーコンの定常の光 |
| 盾型の `guard`（守り）が減った | 盾の亀裂 |

### 8.1 フラッシュの強さ（設定）

- 設定の画面（タイトル・ポーズの「操作の設定」）に「フラッシュの強さ」の行。決定で 標準 1.0 → 弱め 0.5 → 最小 0.2 と切り替える（キーボード・パッドの決定。
  スマホは選んでいる行をもう一度タップ、行は実寸 48px 以上）。`user://input.cfg` の `options/flash` に保存し、「初期に戻す」で標準に戻る（`PadConfig.flash`）。
- main が毎刻み `apply_flash()` で入れる：
  - `Fx.flash_scale`：大きな光（弱点・破断・撃破・突きの衝突・叩きつけの接地・溜めの放出・封印の星など、`_cf` で出す光）の明るさに掛ける。
  - `Vfx.flash_scale`：足し合わせの層の粒の明るさ（色のいちばん強い成分 × 濃さ）が 0.6 を超える分を同じ倍率に縮める（銃口・ダッシュの踏み出し・警戒の閃き・光柱など、
    `_cf` でない明るい光の頭）。暗い光（通常の命中・火花・輪）と半透明の層（煙・破片・色の地）は変えない。標準では何もしない。
  - `EnemyView.flash_scale`：攻撃を受けた番機の白磁の殻が白く光る強さ（閂の胴は画面の大きな面になる）。
  - `Hud.flash_scale`：被弾の画面の赤（全画面。標準で最大 0.24、0.4 秒で消える）。
- 全画面の光を探した：上の被弾の画面の赤だけ。部屋の移動・やり直しの暗転と奈落の暗さは黒で光らないので対象にしない。
  第 1 章の台本の手順に画面を白くするものは無い（`shake` は画面の揺れ）。閂の撃破・破断などの大きな光も 0.1〜0.5 秒・数 m の光で、画面全体は光らない。
- `flash.jpg`：鼻先の弱点の命中（殻の光と閃き）・被弾の画面の赤・突きが壁に刺さった衝突を 3 段階で並べた。最小でも光る場所と向きは分かる。

### 8.3 フレームの装着（適合のイベントに合わせた）

- 台本に見た目の合図の手順 `{"fx": "frame_fit", "part": "core" | "arm" | "legs"}` を足した（Story は出来事 `{type: "fx"}` を出すだけ。待たない。遊びは変えない）。
  Fx は合図でその部位の装着のエフェクトを出す。台本の途中で力が付いた部位（力のフラグが先に立つ）は、合図か台本の終わりまで部品を隠しておく（`PlayerView.reveal_later`）。
  台本の外で付いたとき（確認用のフラグ・`--flags` など）は今までどおりすぐ出す。
- 封印室（`ch1.frame_fit`）：前はナレーション（`ch1.fit.b`）のあとにフラグが立ち、カメラは台座の方を向いたまま、ナゴミの「起動シーケンス完了」の会話の窓の下で部品が付いていた（ほとんど見えない）。
  今はナレーションのあと、カメラをハルの斜め前（`eye`、1 秒で移る）へ回し、0.5 秒後に適合（胴の部品）→ 揺れと音 → 装着が見える 1.9 秒を待ってから、カメラを戻してナゴミが話す。`frame_fit_core.jpg`。

### 8.8 無敵の点滅（残り）

- しなかった。見本は琥珀の縁の光。縁の光（フレネル）は標準の材質に無いので、ハルの全部の面に足し合わせの第 2 の材質（`next_pass`）を重ねることになる。
  新しいシェーダーは初めて描くときに組み立てる（gl_compatibility では特に引っかかる）ので、読み込みの間に一度描いておく仕組みと、初めて光るこまの時間を両方の描き方で測る確かめが要る。今回はそこまでしなかった。
- するときの案：(1) ハルの材質の発光（`emission_enabled`）を読み込みのときから黒で入れておき、無敵の間は発光の色だけを琥珀（0.25 以下）にして脈打たせる
  （シェーダーは変わらないので組み立ては読み込みのときだけ。ただし縁ではなく体全体がほのかに光る）。(2) 縁の光の `next_pass` を、部屋の読み込みの暗転の間に見えない所で 1 こま描いて組み立てておく。
