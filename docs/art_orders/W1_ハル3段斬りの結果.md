# ハルの 3 段斬りの動作を作り直した結果（haru_r）

> 2026-10-07。ユーザーの指摘「攻撃の動作が、人形を動かしているように見える。特に剣（光刃）で斬る動作」（残課題 G1）を受けて、
> 主人公ハルの 3 段斬り（combo1・combo2・combo3）だけを先に作り直した。モデル（骨・形・塗り・手）は触っていない。
> 跳躍・突き・溜め・空中斬り・銃の反動は、この結果をユーザーが見てから（5 章）。

## 1. 何が「人形」に見えていたか

| 原因 | 中身 |
|------|------|
| 姿勢 3〜4 個をなめらかに等速でつないだだけ | 予備動作（振りかぶり）、一瞬で振り抜く速いこま、振り切ったあとの行き過ぎと戻りが無い。関節を補間で回しただけに見える |
| 動くのが左腕と胸だけ | 腰・脚は「構え」の 1 姿勢で固定、頭も右腕も動かない。体重の移動が無い |
| 足が浮く | 構えの脚の角度だと両足が床から 3〜4cm 浮いていた（腰を下げていない） |
| ゲーム側と合っていない | 動作の長さと中身の攻撃時間（0.28・0.30・0.45 秒）は別々、当たり判定（25〜70%）と振り抜くこまが無関係。ヒットストップで中身が止まっても動作は進んでいた。斬撃の軌跡（光る弧）は腕と無関係に 20〜70% を等速で回っていた |
| 30fps | 振り抜きが 2 こまで、速い所の形を置けない |

## 2. 作り方（新しい仕組み）

| 何 | どこ | 中身 |
|----|------|------|
| こまのつなぎ | `tools/blender/lib/humanoid.py` の `Clip` | こまごとに次のこままでの補間を指定できる（`LINEAR`・`QUAD`・`SINE`・`CUBIC` と `EASE_IN`／`EASE_OUT`）。指定が無ければ従来どおりなめらか（ベジエ）。`fps`（従来 30、斬りは 60）、`ground`（接地） |
| 60fps | 同上 `SCENE_FPS` | 書き出しの標本を 1/60 秒に。従来の 30fps の動作はこまの番号を伸ばすだけで、動きは同じ（Godot の取り込みも `animation/fps=60`） |
| 接地 | 同上 `ground_offset`・`bake_clips` | 各こまで足の裏（つま先・かかと）の一番低い点が床に着くように root を下げる（書き出しの標本ごとに測り直す）。浮いているほうの足は、つま先が床に触れるまでかかとを上げる |
| 姿勢の書き方 | `tools/blender/models/humanoid_anims.py` の `sp()`・`k()` | 腰のひねり・背骨と胸（前傾, ひねり）・首・頭・肩（すくめ, 前出し）・上腕・肘・脚・かかと、で全身の姿勢を 1 行で書く。足首は脚の角度から自動で床に合わせる（`feet_for`） |
| 動作だけ焼き直す | `tools/blender/recon/rebake_anims.py` → `splice_anims.py` | 今の `haru_r.glb`（骨・形・塗り）に `humanoid_anims.py` の動作だけを入れ直す（1 分）。絵からの完全な再構築（40 分、`build/recon` が要る）は不要。焼き直しは `build/rebake/` に書き出し、直した動作だけを `splice_anims.py` でゲームの GLB に差し込む（8 章。Blender で読み込み→書き出しをすると頂点が増え、焼き直さなかった動作は長さが半分になるため） |
| 数値の確認 | `tools/blender/recon/motion_check.py` | 各こまの刃の先の位置、刃と頭・胴・脚の距離、足の裏の高さ、腰の沈み。軌跡の図 `build/motion/<動作>_path.png` |
| こま並べ | `tools/blender/recon/motion_sheet.mjs`（確認ページの描画）、`godot_motion_sheet.gd`（Godot の描画） | 横に時間、縦に方向。当たり判定の時間に ● |
| ゲーム側 | `godot/scripts/view/player_view.gd` | 攻撃の動作は中身の攻撃時間と同じ長さで流す（`speed_scale = 動作の長さ / 攻撃時間`）。ヒットストップ中は `speed_scale = 0`（当たったこまで止まる） |
| 斬撃の軌跡 | `godot/scripts/view/fx.gd` | 当たり判定の始まりから 0.06 秒（振り抜きと同じ時間）だけ回して消える |

glTF の書き出しは 1 こま目を 0 秒にした（`export_anim_slide_to_zero`。Godot の動作の長さ = 定義の秒数）。

## 3. 3 段斬りの設計

- 形：**予備動作**（振りかぶり。ゆっくり始めて加速、`QUAD` の `EASE_IN`）→ **振り抜き**（3 こま = 0.05 秒。`QUAD` の `EASE_IN` で最後が一番速い）→ **行き過ぎ**（2 こま。勢いで少し先まで）→ **戻り**（ゆっくり止まる）。
- 全身：腰（±4〜8 度）・背骨（±5〜11 度）・胸（±10〜20 度）のひねりで刃を運び、首と頭は逆にひねって顔を相手に向けたまま、右腕（銃）は反対へ振る。肩は振り抜きで前へ出す。
- 脚：前（左）の足を踏み込み、膝の曲げで腰が 2〜5cm 沈む（3 段目は 10cm）。後ろの足はつま先立ち。
- 長さは中身の攻撃時間と同じ（1 段目 17 こま = 0.283 秒、2 段目 18 こま、3 段目 27 こま）。1 段目・2 段目は振り抜きを攻撃時間の 25%（当たり判定の始まり）に置く。
  3 段目だけは、当たり判定の始まり（0.45 秒の 25% = 0.1125 秒）が頂点で止まるこま（6〜7 こま目）にあり、叩きつけはその後の 0.133〜0.167 秒（2026-11-05 の見直しで分かった。前からそう。8 章）。
- 各段の終わりの構え = 次の段の始めの構え（`READY_L`・`READY_R`）。
- **刃の振り幅**（2026-11-05 に 1 段目と 2 段目を入れ替えた。8 章）：1 段目は左上（左前 68 度、振りかぶりで頭の左上）→ 右 100 度 → 右前 51 度、2 段目は右上（右 108 度）→ 左 77〜79 度 → 左前 53 度、3 段目は左前 53 度 → 頭の上 → 右前 50 度の床近く。最初は左後ろまで 180 度回していたが、ゲームのカメラ（真後ろ、5.5m、見下ろし 12 度）からは刃が腕に隠れて見えなかった。刃は体の前〜横に置く。
- 3 段目：左上へ振りかぶり（上腕 X -155・Z +28。頭から 0.26m 離れる）、背を反らしてつま先立ち → 踏み込みながら右前へ斜めに叩きつけ（前傾 40 度）→ 沈んだ姿勢を 0.1 秒保つ → 立ち直り。
- 腕の回転の注意：胸の前傾は腕を世界では同じ角度だけ**後ろ**へ回す（剛体の回転）。前傾 40 度で刃を前下 65 度に向けるなら上腕 X は -105。頭の上まで上げた腕は、Z の向きが逆になる（正で外へ）。

| 脚 | 踏み込み 25→40 度、腰の沈み 2〜3cm | 踏み込み 20→46〜48 度、腰の沈み 5〜6cm（1 段目）・10〜11cm（3 段目）。3 段目は前の膝を上げて（足を 7cm 浮かせて）から踏み下ろす |

分かったこと（仕組み側）：
- **腰の前傾は脚ごと回す**ので、太ももの角度から腰の前傾を引かないと、前の足が前へ・後ろの足が上へずれて浮く。`sp()` の `legs` は世界での角度とし、腰の前傾を太ももから引くようにした。
- 脚の高さの見積もりは、基準の姿勢の脚の傾き 4 度（`LEG_REST`）を入れると実測（`leg_table`：前に振った脚は見積もりより 2〜3cm 低く、後ろは 2〜3cm 高い）に合う。
- 踏み込みで後ろの膝を曲げると、後ろの足が高く浮いてつま先でも届かない。踏み込みでは後ろの膝を伸ばす（すね 2〜8 度）。
- 上げた足は `lift=(True, False)`・`k(..., lifted=('foot.L',))` で床に合わせない。

確認：`motion_check.py` 問題 0（両足の裏は全こまで床から −0.000〜+0.002m、上げた足だけ +0.07）。画像は `haru_r_trial/motion_new_*.jpg`（2 回目）、
`motion_v1_*.jpg`（1 回目）、`motion_old_*.jpg`（旧）、`motion_godot_*.jpg`（2 回目の Godot の描画）。

## 8. 1 段目と 2 段目の入れ替え（2026-11-05）

ユーザーの指摘：「1 段目と 2 段目の動きを入れ替えてほしい。今は 2 段目と 3 段目がほとんど同じ向きに斬っていて、とても不自然。
ふつうは右から左、上から下へ振ったら、その振り戻しで次の斬りに入る。交互に斬るようにしたい」。

旧は 1 段目が右から左、2 段目が左から右、3 段目が左上から右前下で、2 段目と 3 段目がどちらも左から右へ流れていた。
1 段目と 2 段目の動きを入れ替え、振り終わった刃のある側から次の段が始まるようにした（右・左・右と交互）。

| 段 | 旧 | 新 | 刃の先（新。本人から見た向き・高さ） |
|----|----|----|------|
| 1 段目（17 こま） | 右 → 左（横薙ぎ。銃の腕を真横へ） | **左上 → 右**（旧の 2 段目の動き。待機から入る） | 左前 68 度・1.62 m → 振りかぶり 頭の左上 1.94 m → 右 100 度・0.95 m（行き過ぎ 112 度）→ 右前 51 度・0.88 m（`READY_R`） |
| 2 段目（18 こま） | 左 → 右（切り返し） | **右 → 左**（旧の 1 段目の動き。銃の腕を真横へ振る反動もそのまま） | 右前 51 度 → 振りかぶり 右 108 度・1.67 m → 左 77〜79 度・0.79 m → 左前 53 度・1.12 m（`READY_L`） |
| 3 段目（27 こま） | 右前（`READY_R`）から左上へ振りかぶって叩きつけ | 左前（`READY_L`）から左の上へ持ち上げて叩きつけ | 左前 53 度・1.12 m → 頭の上 2.01 m → 頭の後ろ 1.67 m（頂点で 1 こま止まる）→ 右前 50 度・0.43 m |

何を動かしたか（`tools/blender/models/humanoid_anims.py`）：
- `combo1`：旧の `combo2` の振りかぶり・振り抜き・行き過ぎ・戻りの姿勢を、旧の `combo1` のこま割り（1・4・5・6・7・9・14・18）に置いた。
  待機から入るので、1 こま目は旧の 1 段目の 1 こま目と同じ考えで「左への巻き込みが 7 割ほど進んだ姿勢」（待機から 0.05 秒で混ぜて入る）。
  そこから 3 こま（`QUAD` の `EASE_IN`）で頭の左上の振りかぶりへ行き、振り抜く。予備動作の長さは旧の 1 段目と同じ。
- `combo2`：旧の `combo1` の姿勢（銃の腕を真横 85 度へ振り抜く）を、旧の `combo2` のこま割り（1・5・6・7・8・10・15・19）に置いた。
  始めは `READY_R`（1 段目で右へ振り切った構え）から、そのまま右後ろ上へ巻き込む。
- `combo3`：始めを `READY_L` にし、振りかぶりの前半を直した。刃はもう左にあるので、旧のように体の前を右から左へ横切らず、
  左の外を通って頭の上へ持ち上げるだけになる（距離が短い）。旧の `CUBIC`/`EASE_IN` 6 こまのままだと最初の 3 こまがほとんど動かず止まって見えるので、
  4 こま目に持ち上げの途中（`RISE_3`：全体の 4 割強、前の膝も上がり始める）を置き、そこまで `QUAD`/`EASE_IN` で加速、頂点へは `SINE`/`EASE_OUT` で減速して、
  頂点で 1 こま止まってから叩きつける（頂点・叩きつけ・沈み・立ち直りのこまは旧と同じ）。
- `READY_L`・`READY_R` の姿勢は変えていない（どの段の終わりかの説明だけ直した）。

変えていないもの：各段の長さ（17・18・27 こま = `tuning.yaml` の `comboTimes`）、振り抜きを攻撃時間の 25%（当たり判定の始まり）に置くこと、
予備動作 → 振り抜き 3 こま → 行き過ぎ 2 こま → ゆっくり戻る、の形、腰が先に回る `LEAD_1`・`LEAD_2`、ひねりと腕の振りの大きさ（2〜3 回目に決めた量）。
ゲームの中身の数（威力 10・10・22、攻撃時間、踏み込み 0.8 m、届く距離 2.2 m、3 段目で浮かせる）は段の番号のまま。

振りの向きに合わせて直したもの：
- 斬撃の帯（`godot/scripts/view/fx.gd` の `_slash`）：帯が伸びる向き（`swing`）を、1 段目は左上 → 右、2 段目は右上 → 左にした。
  旧は 1 段目・2 段目とも帯が斜め上へ伸びていたが、刃は斜め下へ振り下ろしているので、下へ伸びる向きに直した。
  3 段目は旧は「縦に切り上げ」（下から上へ）で、叩きつけと逆だったので、左上から右前下へ伸びるようにした。
  初めは縦に立てたまま向きだけ逆にしたが、見直しで「ゲームのカメラから縦の細い線に見え、上の端が 3.3 m（刃のいちばん高い所 2.0 m より 1.3 m 上）まで届く。下半分はハルの体に隠れる」と分かったので、
  半径を 3.1 → 2.6 m にし、横へ倒した（上の端は左前の 2.3 m の高さ、先は右前（右 1.7 m・前 1.8 m）の床）。ゲームのカメラから左上 → 右下の斜め 45 度の弧に見え、ハルの体の右を通る。
- 帯の半径（1.8・2.2・2.6 m）と明るさは、段が進むほど大きくする盛り上がりで、動きの向きではない（当たり判定の届く距離はどの段も 2.2 m）ので、段の番号のまま。
- ほかに段ごとに向きのある物は無かった：当たったときの火花・吹き飛び・当たる順・画面の揺れ・音（左右の振り分けは無い）は段で変わらない。
  確認の撮影の名前（`vfx_b1_combo1` など）は段の番号なので、そのまま。

元の GLB の選び方（見直しで直した）：初めは差し込みも焼き直しも `BASE_REV`（`06ea887`）の GLB を元にしていたが、この版の combo1〜3 は旧のままなので、
次に別の動作を直して `--clips idle` などで差し込むと、combo1〜3 が黙って旧に戻った（差し込みの道具の比べも同じ元と比べるので通ってしまう）。
今は、`splice_anims.py` と `rebake_anims.py` の元の GLB は「形が `BASE_REV` と同じ物のうち、いちばん新しい物」（作業中の `haru_r.glb` → だめなら git の HEAD）。
`BASE_REV` は形の手本として、元の形が同じかを確かめるのに使う。どちらも形が違えば止まる（Blender で書き出した物をそのままコミットした、または完全な再構築をして `BASE_REV` を直していない）。
また、`rebake_anims.py --only` で焼き直さなかった動作は、Blender の読み込み・書き出しで長さが半分になる（idle 2.0 → 1.0 秒、run 0.667 → 0.333 秒）ので、
焼き直しの書き出しは既定で `build/rebake/haru_r.glb` に置き、ゲームの GLB は上書きしないようにした（`splice_anims.py --from` の既定もそこ）。
