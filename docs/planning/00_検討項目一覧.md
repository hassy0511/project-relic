# Project RELIC 企画検討項目一覧（大粒度・初版）

「ロックマンDASHのような3Dアクションアドベンチャー」を作るにあたり、
企画を練り上げるために決めるべき論点を大きな粒度で洗い出したもの。
この一覧を精査・確定させてから、各項目の中身の検討に進む。

---

## A. プロジェクト基盤（他のすべてを縛る根幹決定）

| ID | 項目 | 決めること |
|----|------|-----------|
| A1 | ゴール・完成定義・スコープ | 想定プレイ時間、何をもって「完成」とするか、垂直スライス（MVP）からフル版への段階の切り方、「一気に実装」の単位 |
| A2 | プラットフォームと技術スタック | ブラウザ（Three.js / Babylon.js + TypeScript）、Godot、Unity などから選定。評価軸は「Claude がコンテナ内でビルド・自動プレイ・スクショ確認まで回せるか」 |
| A3 | アセット制作戦略 | 3Dモデル・アニメーション・テクスチャ・BGM/SE の調達方法（プロシージャル生成／ローポリの自作／CC0 素材／外部生成ツール／人の手作業）と分担。**最大のリスク** |
| A4 | 権利・オリジナリティの線引き | 「DASHらしさ」は継承するが、固有名詞・キャラデザイン・楽曲などは使わない。どこまで寄せ、どこから独自性を出すか |

## 依存関係と推奨する検討順

```
A1 ゴール・規模 ─┐
                 ├─→ A2 技術 / A3 アセット ─→ C 群（システム） ─→ D / E ─→ F
B1 コアピラー  ──┘           │
                            └─→ D1 アート（A3 と一体で決める）
B2 世界観 / B3 キャラ … B1 の後、C 群と並行で可
A4 権利 … B2・B3・D1 の各段階で都度チェック
```

1. **A1 + B1**：「何を作りたいか」を先に固める
2. **A2 + A3 + D1**：「それを実現できるか」を一体で判断する（ここが最重要の分岐点）
3. **B2 / B3 / C 群**：中身の設計
4. **D / E**：表現と技術の詳細
5. **F**：実装計画に落とす

## 特に重い論点（初見）

- **A3 アセット**：コードは一気に書けても、3Dモデル・モーション・音は別問題。
  DASH の PS1 ローポリ感は、プリミティブ＋プロシージャルで作る方針とむしろ相性が良い。
- **垂直スライスを挟むこと**：「街ひとつ＋遺跡ひとつ＋ボス一体」で面白さを確かめてから量を作る。
  一気に作る場合でも、この区切りは設けた方が手戻りが小さい。
- **C1/C2 の手触り**：DASH の面白さの中心はロックオン射撃の気持ちよさ。
  数値調整は人が実際に遊ばないと詰めきれないため、F2 のフィードバック経路を早めに用意する。
